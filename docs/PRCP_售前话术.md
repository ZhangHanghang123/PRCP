> **目标客户**：股份制商业银行 / 城商行 / 农商行的 **计划财务部 / 资产负债管理部 / 风险管理部 / 金融市场部**决策层
> **核心定位**：**基于账户册的银行级经营计划与资产负债预测一体化平台**
> **差异化亮点**：**端到端建模 + AI 算法可插拔 + 监管指标闭环 + 反算驾驶舱所见即所得**

## 二、银行业当前的 5 大痛点（话术钩子）

在与客户交流时，从以下 5 个真实痛点切入，每个都附"我们的解法"。

### 痛点 1：账户册与业务系统脱节，预测口径"千人千面"
- **现状**：核心系统、FTP 系统、风险系统各自维护一套账户层级结构，每次经营计划会议，**总行 / 分行 / 支行**数据对不上，部门间反复拉表对账。
- **PRCP 解法**：**统一账户册（COA）底座**，5 层树形结构 + 位置分层编码（S01010100=S01 资产 / S0101 贷款 / S010101 境内人民币），**一套口径，全行共用**。所有后续模块（报表、指标、模型、反算）都基于这套账户册自动取数。

### 痛点 2：24 个月滚动预测全靠 Excel 手工拼
- **现状**：资产负债管理部每月末出 24 个月预测，需要 3-5 个分析师用 Excel 拉数，**口径一变，全表重做**；到期续作 / 新业务 / 利率传导无法自动联动。
- **PRCP 解法**：**64 桶期限结构**（1-60 月按月 + 长端 5/10/15/20/30 年）+ **新业务模拟引擎**（按月滚动 5 步算法，到期还本 + 续作 + 新业务叠加全自动），**配置一次跑出 24 月**。

### 痛点 3：监管指标（LCR/NSFR/CET1/△EVE）算不清、算不快
- **现状**：5/7/8 号规则、IRRBB 经济价值变动、流动性覆盖率，每季度报送靠**手工算 + 多次返工**；一个口径变更需要重算所有数据。
- **PRCP 解法**：**6 大监管指标全自动计算**（LCR/NSFR/CET1/ROE/NIM/△EVE）+ **指标评分雷达图**（5 维评分一屏看），**红线阈值自动预警**。

### 痛点 4：模型（AI / 计量）接入门槛高
- **现状**：分行想做对公存款增长预测，找数据科学家写 Python 脚本；总行想做利率风险建模，找外部咨询公司；**模型上线周期 3-6 个月**。
- **PRCP 解法**：**算法字典化 + 即插即用**，预置 12 种算法（DNN 神经网络、蚁群算法、非线性求解、线性规划、线性回归等），业务方**选算法、配参数、点训练**，**小时级出结果**。

### 痛点 5：反算 / What-If 分析能力弱
- **现状**：高管问"如果明年净息差再降 20bp，我们的 ROE 和资本充足率会怎么变？"，**IT 排期 2 周才能出表**。
- **PRCP 解法**：**组合反算驾驶舱**（首页大屏）+ **5 指标 24 月趋势实时联动**，**切换方案 / 调整参数秒级响应**。

## 三、PRCP 核心价值主张（6 大主张）

### 主张 1：业务链路一体化 — "从账户册到反算，一个平台全包"

```
   ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
   │ ① 账户册 │─▶│ ② 报表   │─▶│ ③ 数据   │─▶│ ④ 指标   │─▶│ ⑤ 模型   │─▶│ ⑥ 反算   │
   │   维护   │  │ 表项管理 │  │   维护   │  │   管理   │  │   训练   │  │   驾驶舱 │
   └─────────┘  └─────────┘  └─────────┘  └─────────┘  └─────────┘  └─────────┘
       基础建模      6 类报表       9 类数据      公式/函数      12 种算法     5 维雷达
       父子层级      取数逻辑       64 桶矩阵     指标评分      KPI 方案关联   24 月趋势
       5 层树形      树形表项       Excel 导入    试算分数     超参数模板     大类分布
                                                                              节点热力图
```

> **话术**："我们不是又给您上一个新系统，我们是**把您行内目前散落在 Excel、核心系统、风控系统的 6 段业务，合并成一条贯通的数据流水线**。从此**账户册变、报表自动变、指标自动变、模型自动变、反算自动变**。"

### 主张 2：账户册底座 — "一次建模，全行共用"

- **5 层树形结构**（L1-L5），支持父子层级、拖拽排序、软删除复活
- **位置分层编码**（S01/S02/S03/S04 四大类），**自动识别**资产/负债/权益/表外
- **内置中信银行账户册方案**（ZXCOA_V1）：38+ 节点，含"境内各项人民币贷款 / 1.1 对公一般贷款 / 1.2 个人贷款 / 1.3 信用卡贷款 / 1.4 票据贴现 / 1.5 非银贷款"等
- **64 桶期限结构**：1-60 月按月 + 长端 5/10/15/20/30 年，覆盖所有资产业务的期限

> **话术**："中信银行现有账户册 5 层 38+ 节点已经在我们平台里跑通了，**原系统余额 8.38 万亿与新平台计算结果完全一致**。您行只要导一份账户册 Excel，**5 分钟完成全行口径统一**。"

### 主张 3：监管指标闭环 — "5 号规则、LCR、NSFR 自动算、自动预警"

| 监管指标 | 监管要求 | PRCP 实现 | 价值 |
|---|---|---|---|
| **LCR 流动性覆盖率** | ≥ 100% | 全自动 + 分段/线性双评分 | 0 手工，秒级出 |
| **NSFR 净稳定资金比例** | ≥ 100% | 全自动 + ASF/RSF 折算 | 折算规则可视化 |
| **CET1 核心一级资本充足率** | ≥ 7.5% | 全自动 + RWA 风险权重 | 11 类资产自动加权 |
| **△EVE 利率风险经济价值变动** | ≥ -15% × Tier1 | 6 情景利率冲击 + 久期加权 | IRRBB 报送一键出 |
| **ROE 净资产收益率** | 8-15% | 净利润/平均净资产自动算 | 业务归因可拆解 |
| **NIM 净息差** | 内控阈值 | 生息资产/计息负债利率自动加权 | 利率传导可追溯 |

- **6 类监管参数表**（LCR/NSFR/CET1/EVE/NIM/ROE），每张表独立的折算系数 + 运算符 + 风险权重维护
- **5 指标 24 月趋势图** + **5 维指标评分雷达图**，**红线预警**自动触发

> **话术**："过去您们 1 个分析师 1 周才能算完 1 次 5/7/8 号规则报送，现在**配置一次，24 月自动出**。而且每跑一次，平台都帮您**追溯到具体账户册节点**——出问题时不再是'数字异常'，而是'1.2 个人贷款的第 3 季度久期不对'。"

### 主张 4：模型可插拔 — "12 种算法，小时级训练"

- **预置 12 种算法**：
  - **经典计量**：线性回归、线性规划、非线性求解
  - **AI 算法**：DNN 神经网络、蚁群算法、随机森林
  - **金融专用**：久期加权、利率敏感性、VAR/CVAR
  - **场景生成**：HJM 模型、PCA 拟合、Svensson/NS/NSS 利率曲线拟合
- **超参数模板**（6 类 18 项）：每类模型预置典型超参范围，业务方**下拉选 + 调数字**即可
- **训练任务管理**：选算法 → 选账户册方案 → 选数据日期窗口 → 点训练，**全流程 1 个页面**

> **话术**："您不需要懂 Python，也不需要懂 TensorFlow。**选算法、选参数、点训练**——就像您在手机上点'一键修图'一样。**模型版本管理、参数版本管理、训练日志**全在平台里，**审计可追溯**。"

### 主张 5：反算驾驶舱 — "决策层看一屏，就够"

- **首页驾驶舱 4 行布局**：
  1. **8 个 KPI 卡**（资产余额、负债余额、贷款加权平均利率、ROE + CET1/LCR/NSFR/△EVE）— 一眼看全
  2. **5 指标 24 月趋势** + **5 维评分雷达图** — 趋势 + 健康度
  3. **Top 10 节点**（按余额）+ **大类分布**（饼图+柱图）— 资产结构
  4. **节点 × 指标热力图**（全宽）— 风险定位
- **实时联动**：切换方案 / Run / 预测月份，**全屏秒级响应**
- **节点级穿透**：热力图点击节点 → 跳转账户册详情，看每个账户的余额 / 利率 / 利息收支

> **话术**："您下次开资产负债委员会，**不用 PPT**。直接打开 PRCP 首页——**'中信银行 2026 经营计划'方案，第 8 次运行，2026-12 月**。8 个 KPI 卡片 + 5 指标趋势 + 节点热力图 + 风险预警，**全在一屏**。领导问'这块怎么变了？'，**点一下节点就能穿透到账户级**。"

### 主张 6：技术架构先进 — "中信银行验证、生产可用"

- **前后端分离** + **64 桶共享**（`BasicDataBuckets` 公共类，原 Python + 现 Java 双版本对齐 < 1e-6 精度）

- **30+ 张表 / 完整数据字典** / **审计日志全留痕** / **软删除 + UNIQUE 复活** / **JWT + 角色权限**
- **生产级部署**：HTTPS + nginx 反代 + systemd 自启 + 每日备份 + 90 天证书自动续期

> **话术**："我们不是 demo，**是已经在中信银行跑生产**的系统。**9 大业务模块全量上线、组合反算驾驶舱为行领导日常决策工具**。技术栈选型前沿（Vue 3 / Element Plus / ECharts / FastAPI / SQLAlchemy 2 / Spring Boot 2.7 / MyBatis-Plus 3.5）但又**对运维友好**（单机部署 + 容器化友好 + 完整中文文档）。"

## 四、产品功能模型先进性（6 大技术亮点）

### 亮点 1：64 桶期限桶结构 — "业内首创"

- 1 年内按月（m1-m12） + 2-5 年按月（m13-m60） + 长端 5/10/15/20/30 年
- **原期限桶 + 剩余期限桶**双套共 128 列，覆盖：
  - **资产业务**：贷款到期分布、债券剩余期限
  - **负债业务**：存款到期、债券发行剩余
  - **利率传导**：FTP 计算的逐月利率
- **跨模块共用**：`BasicDataBuckets.java` 公共类，**Python/Java 数值精度对齐 < 1e-6**（用 BigDecimal 而非 double）

> **话术**："**64 桶 + 64 桶 = 128 列**——这是我们平台的'独门武器'。**所有监管指标、模型训练、反算预测**都基于这个统一的期限结构计算。**您不需要再问'这个指标按什么口径算'**——所有口径都是这 128 列的视图。"

### 亮点 2：算法字典化 + 超参数模板 — "12 种算法开箱即用"

- **算法注册中心**（Python `algorithms/` + Java `algorithms/`），新算法只替换实现，**前后端不改**
- **6 类超参数模板**（线性类、神经网络类、优化类、回归类、分类类、风险类），每类 3 个预置参数项
- **KPI 方案关联**：模型训练结果直接绑定 KPI，**指标和模型天然打通**
- **训练任务异步化** + 进度条 + 日志实时查看 + 训练结果可对比

> **话术**："**算法 = 字典配置**，不需要写代码。**超参 = 模板下拉**，业务方点 3 下就开跑。**模型版本 + 参数版本 + 训练日志**全留痕——**审计合规直接通过**。"

### 亮点 3：5 步法反算引擎 — "到期还本 + 续作 + 新业务，自动滚动"

```
   T 月 → T+1 月：到期还本 (M1 桶归零)
                  → 自动续作 (按节点的期限占比 + 利率分布)
                  → 叠加新业务 (按节点的年化增长比例)
                  → 重新计算主指标 (current_balance / avg_balance / weighted_rate)
                  → 递归聚合 SUMMARY 节点
```

- **5 步算法步骤 1-5**：桶推算 + 月份推算 + 主指标重算 + 叶子汇总 + 父节点聚合
- **新业务模拟方案**可作为反算驾驶舱的**预测输入**
- **预测期可配**（默认 24 月，可延展至 60 月）

> **话术**："反算 = 24 月的'资金时间机器'。**今天存 100 亿 1 年期，到期会自动滚续为新的 1 年期**；**新增 50 亿 5 年期，按既定节奏释放**。**业务规则配一次，24 月自然流出**。"

### 亮点 4：函数指标可热重载 — "改完脚本立即生效"

- **白名单**（`kpi_function_runner.py`）+ **importlib 动态加载** + **mtime 监听**
- 业务方修改 `pnn_cet1.py` 公式 → 保存 → **下次调用立即生效**，**无需重启服务**
- **ctx dict**（kpi_values/rpt_items/ctx_extra/data_date）— 上下文自动注入
- **可扩展**：用户后续提供的算法只替换 `services/` 下的实现

> **话术**："**改一个公式 = 改一个 .py 文件**。**保存即生效**，**不需要运维配合**。**业务分析师 + 数据科学家的工作流彻底打通**。"

### 亮点 5：通用字典 + DictProvider — "国际化、可扩展"

- **sys_dict 单表** + **14 类 65 项**字典（指标单位、节点类型、状态等）
- **DictProvider Context**：前端通过 React Context 注入字典，**避免硬编码**
- 字典项变更 → **前端自动刷新**，**不需要发版**
- 支持中英文切换（码值存英文，Context 注入时翻译）

> **话术**："**'PERCENT' 这个码值，3 个月后想改叫 'PCT'？**——**改一行数据库，前端自动跟着变**。**0 发版、0 改代码**。"

### 亮点 6：组合反算驾驶舱 — "全行决策的'控制塔'"

- **首页一屏** = 行领导每天看的"驾驶舱"
- **4 行布局** + **实时联动** + **节点级穿透**
- **5 维评分雷达图**：ROE / CET1 / LCR / NSFR / △EVE 综合评分（0-100），**低于 60 触发预警**
- **节点 × 指标热力图**：红黄绿三色，**一眼定位风险节点**
- **Top 10 节点**：按当前余额 / 月均余额 / 利息收支多维展示

> **话术**："这个驾驶舱是**为行长 / CFO / 风险总监**设计的。**打开浏览器，输入 URL**，**经营情况一屏到底**。过去您要拉 5 张报表拼 1 个 PPT，现在**1 秒出图**。"

## 五、典型客户场景（3 个真实场景）

### 场景 1：某股份行计划财务部 — "2027 年经营计划编制"

- **客户现状**：每年 10-12 月编制次年经营计划，**总行 + 36 家分行**，**5 个分析师 + 2 周时间**，主要工作是拉 24 月 Excel 滚动表
- **PRCP 价值**：
  1. **账户册统一**：总行账户册方案一次性下发，**36 家分行共用**（每行可单独维护子方案，但口径一致）
  2. **指标计算自动化**：5/7/8 号规则配置后，**24 月自动出**（每跑 1 次 < 1 分钟）
  3. **新业务模拟**：每个分行的对公存款 / 零售贷款增长率 + 期限占比 + 利率分布，**1 次配置 24 月自然出**
  4. **What-If 情景**：行长问"净息差再降 20bp"——**改 1 个参数，全图自动重算**

> **话术**："**5 个分析师 2 周的工作，1 个人 1 天做完**。**剩下 4 个分析师做什么？**——**做业务分析、做策略优化**，**而不是做表**。"

### 场景 2：某城商行风险管理部 — "IRRBB 利率风险报送"

- **客户现状**：IRRBB（利率风险银行账簿）报送需要 6 个利率冲击情景（±100bp / ±200bp / 短期向下 / 短期向上），每个情景算 △EVE + △NII，**全手工 Excel 拼**
- **PRCP 价值**：
  1. **6 情景自动生成**（EVE Param 模块 + Svensson 曲线拟合）
  2. **久期加权自动算**（避免手工算 PV 折现）
  3. **△EVE 红线预警**（超 -15% × Tier1 自动标红）
  4. **历史回溯**：所有报送版本可对比、可追溯

> **话术**："过去 1 个高级分析师 2 周的工作，**配置一次，1 小时出 6 情景**。**报送时直接出图 + 出表**。"

### 场景 3：某农商行金融市场部 — "FTP 内部转移定价"

- **客户现状**：FTP 曲线需要按月维护，13 个期限点（M1/M3/M6/M9/Y1/Y2/Y3/Y5/Y7/Y10/Y15/Y20/Y30）人工收集
- **PRCP 价值**：
  1. **利率管理模块**：13 期限点 + 5 类曲线（国债/政金/同业存单/LPR/FTP）
  2. **Svensson / NS / NSS 自动拟合**（少 1 个点也不影响）
  3. **横向对比**：同一日期不同曲线 / 同一曲线不同日期
  4. **Excel 模板导入导出**（业务方熟悉的工具）

> **话术**："**13 个期限点 = 13 个数字**。**Svensson 拟合自动**——**少 1 个点也不会报错**。**FTP 内部转移价**直接是 13 个期限点的插值，**NIM 预测的输入是 24 月 FTP 曲线**——**全链路打通**。"

## 十、常见客户疑问 Q&A

### Q1：账户册和核心系统对不上怎么办？
**A**：PRCP 账户册是**管理会计口径**，不和核心系统的会计科目一一对应。我们建议**以管理目标为出发点重构账户册**（参考中信银行 ZXCOA_V1 方案），用专门的"对账模块"定期和核心系统核对。

### Q2：算法我们能不能自己加？
**A**：完全可以。PRCP 的算法层是**注册中心模式**——您的数据科学家写一个 `myalgo.py`，丢到 `services/` 目录，**前台自动出现**。**前后端 0 改动**。

### Q3：和我们现有的 SAS 系统冲突吗？
**A**：不冲突。**PRCP 是业务自助平台，SAS 是数据科学家平台**。SAS 适合复杂计量建模（ECL、VAR），PRCP 适合业务人员自助（What-If、监管报送）。两个系统**可以共存 + 数据互通**。

### Q4：部署需要什么环境？
**A**：**最小配置**：2C4G 1 台（开发环境）/**推荐配置**：4C8G 1 台（POC）/**生产配置**：8C16G 2 台（高可用）。操作系统 Linux（CentOS / Ubuntu / 麒麟），MySQL 8.0+。

### Q5：实施需要客户投多少人？
**A**：客户侧投入：
- **业务负责人 1 人**（决策 + 业务规则确认）
- **业务分析师 2 人**（指标配置 + 报表配置 + 账户册维护）
- **IT 1 人**（环境准备 + 部署配合）

我们侧投入：实施顾问 2 人 + 算法工程师 1 人 + 项目经理 1 人。

### Q6：未来 3 年的产品路线图？
**A**：
- **2027 Q1**：对接 IFRS9 预期信用损失（ECL）模型
- **2027 Q2**：增加债券组合优化模块
- **2027 Q3**：增加零售客户级 RAROC 计算
- **2027 Q4**：对接外部数据源（Wind / 央行 / 同业）
