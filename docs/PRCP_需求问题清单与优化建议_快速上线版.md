# PRCP需求说明书问题清单与优化建议

## 评审定位

**本次目标：快速跑通最小业务闭环，不以完整模型平台、复杂优化算法或完整驾驶舱为上线前提。**

本清单仅列需求文档中需要统一或补充的事项，不重复实施方案。建议本期主线为：**基础数据导入 → 统一指标测算 → 一种可执行的反算 → 结果留存、查询与导出**。各项“优化建议”是基于本次上线目标提出的调整方案，不是原文已经规定或代码已经实现的能力。

评审依据：本次上传的《PRCP_需求说明书.docx》，71页解析版本。未检查代码与数据库实际实现，因此以下属于**需求一致性及最小落地条件评审**，不直接判定系统已存在相应缺陷。本清单只讨论功能闭环及需求修正，不替代行内既有的安全、权限、变更与发布要求。

### 位置查找说明

本清单不使用原文附件链接。每处位置提供“**第几页、第几行＋章节/规则或表格行＋原文关键词**”。

**行号口径：**页码沿用本次附件的71页解析结果；行号按该页解析文本从1开始计数，保留表格单元格换行，不计独立的分页/图片标记。因此，这不是Word菜单开启后的排版行号。括号中的全文行号用于精确核对同一份解析文本。表格优先按所列“表名＋字段表第几行”查找。Word因字体、纸张或打印机不同发生重排时，以章节、规则编号和原文关键词为准；

## 二、逐项问题、位置与最小优化建议

### 问题01｜预测周期、月份编号和数据日期含义不一致

**处理级别：本期统一。**

**原文位置与依据：**

- **第3页，第44—46行**（全文L99—L101）；1.2“组合反算”术语，第12项。原文要点：“输出未来20年的资产负债表与关键指标预测结果”。
- **第52页，第13—18行**（全文L2381—L2386）；3.5.3，R8“数据日期一致性”。原文要点：结果data_date取账户册数据日期；未来24月，by_date_offset＝0—23。
- **第17页，第15—17行**（全文L686—L688）；3.2.3，R3“维度键”。原文要点：offset_unit仅允许D（天）/W（周）/Y（年）。
- **第67页，第2—9行**（全文L3152—L3159）；3.6.4，“时间字段统一规范”。原文要点：data_date为预测月份实际日期，date_offset为1..24。
- **第68页，第32—37行**（全文L3216—L3221）；3.6.4，prcp_data_reverse字段表第8行。原文要点：offset_unit默认M，含义为“月”。

**问题及影响：**20年与24个月、0—23与1—24、基期日期与预测日期，以及是否支持M（月）没有统一。即使只做流程打通，也可能出现第一期错位、输入校验拒绝月度数据、查询不到结果等问题。

**本期最小优化建议：**本期固定“未来24个月”；数据库与计算统一采用月份1—24，页面滑块如保留0—23，仅在接口边界转换。将“基期数据日期”和“预测日期”分别定义，明确第一期从基期后的哪个月开始、是否按月末对齐。基础数据与结果的偏移单位统一支持M；若基础数据只维护基期，则固定偏移0并写明转换规则。同步修改接口、校验及文档，不新增20年预测功能。

**可后续完善：**20年预测、多种频率组合、任意预测期数，放到后续扩展。

**最小验收点：**用一个确定的基期执行，第一期和第24期日期正确；导入、计算、查询和导出的月份完全一致。

### 问题02｜基础数据与反算结果的期限桶和表结构不同步

**处理级别：本期统一。**

**原文位置与依据：**

- **第23页，第16—30行**（全文L1024—L1038）；3.2.4，“数据库结构（v4 2026-09-20拆分）”。原文要点：基础数据拆为主表、原始期限子表、剩余期限子表；两类期限各64桶。
- **第24页，第5—7行**（全文L1044—L1046）；3.2.4，“下游消费”说明。原文要点：反算结果“结构完全继承＋反算方案维度”。
- **第68页，第82—101行**（全文L3266—L3285）；3.6.4，prcp_data_reverse字段表第16—17行。原文要点：仍列13个原始期限桶及13个剩余期限桶。
- **第64页，第5—6行**（全文L3015—L3016）；3.6.4，驾驶舱布局第②—③行相关描述。原文要点：期限缺口热力图使用“19节点×13期限”。

**问题及影响：**输入按64＋64桶，输出却仍按13＋13桶列示，且称“完全继承”；未给出聚合映射。开发可能读写不同的字段集合，或在转换时丢失期限信息。

**本期最小优化建议：**优先以已写明的v4基础数据口径作为本期依据，结果存储保留对应期限信息，接口返回结构固定。若驾驶舱为了简洁只展示13档，只在展示层聚合，并补一张“64桶→13档”映射表；不得把13档展示口径直接当作64桶输入结构。同步修正主表/子表说明和结果读写位置。

**可后续完善：**暂不建设可自由配置的期限分桶引擎，也不要求复杂的期限拖拽交互。

**最小验收点：**同一笔数据从导入到结果查询，期限分布能对应、合计金额不变；不存在字段缺失或重复汇总。

### 问题03｜账户册状态规则与反算准入校验冲突

**处理级别：本期统一。**

**原文位置与依据：**

- **第10页，第3—8行**（全文L339—L344）；3.1.3，第9条“状态字段语义”。原文要点：方案与节点统一为ACTIVE/INACTIVE两态。
- **第12页，第46—49行**（全文L487—L490）；3.1.4，prcp_coa_scheme字段表第6行。原文要点：status默认DRAFT，枚举为DRAFT/APPROVED/DEPRECATED。
- **第50页，第3—7行**（全文L2303—L2307）；3.5.2，方案新增与反算触发流程。原文要点：只选择已审核账户册，执行前要求账户册status＝approved。

**问题及影响：**按“启用/停用”创建的账户册，可能不能通过“已审核”条件。文档同时保留两套状态，不能保证账户册建好以后就能发起反算。

**本期最小优化建议：**只保留一套本期实际执行的状态规则，并同步页面、数据库、初始化数据和反算校验。若尚未实现审核流程，可先采用ACTIVE/INACTIVE，反算仅校验“启用”；将文档“已审核”改为“启用可用”，不要把启用状态伪装成已完成审核。若现有代码已经采用另一套枚举，则按现有实现统一定版。

**可后续完善：**独立审批流、多级审核和复杂生命周期可以后续增加。

**最小验收点：**按本期页面新建并启用账户册后，可直接选入反算方案；停用账户册不能新增执行。

### 问题04｜指标取数映射、利率单位和计息口径需要最小定版

**处理级别：本期统一。**

**原文位置与依据：**

- **第29页，第5—19行**（全文L1383—L1397）；3.2.4，“度量字段”weighted_rate、interest_amount、risk_weight行。原文要点：weighted_rate标注为百分比；interest_amount未明确计息期间。
- **第61页，第5—9行**（全文L2903—L2907）；3.6.2，步骤②“快照生成”。原文要点：驾驶舱另写月度NII＝balance×weighted_rate/12，并计算其他指标。

**问题及影响：**公式依赖报表表项，但基础数据字段如何进入表项需要落到配置；基础数据保存校验与驾驶舱计息公式没有交代同一期间和百分比换算规则。文档未明确两条路径是否复用同一计量口径，可能出现“数据保存不了”或同一指标在两个页面数值不同。

**本期最小优化建议：**仅对本期真正展示和参与反算的指标完成口径定版。逐项补齐一张小表：指标编码、来源字段/报表表项、公式、金额单位、利率存储方式、计息期间、符号及缺失值处理。预置必要的报表和表项映射，不必先建设完整报表配置平台。对月度计息明确采用哪种简化规则，并把基础数据校验、指标重算、反算评估和驾驶舱统一调用同一计算函数或同一结果。

**可后续完善：**全部监管指标、逐笔复杂现金流与全量产品计息规则不作为本次跑通的前提；未实现的指标标为“暂不支持”，不填展示数。

**最小验收点：**准备一组业务确认的小样例，人工计算、指标页面、反算结果、驾驶舱和导出数值一致；无有效分母或缺少关键数据时给出明确提示。

### 问题05｜反算需要补齐一个可执行的最小求解规格

**处理级别：本期补齐最小闭环。**

**原文位置与依据：**

- **第50页，第9—11行**（全文L2309—L2311）；3.5.2，反算引擎执行步骤。原文要点：加载模型参数，按节点×期限桶计算24月预测并写结果。
- **第56页，第34—39行**（全文L2611—L2616）；3.5.4，prcp_reverse_scheme字段表第7—8行。原文要点：horizon_months默认24，algorithm列CVXPY_QP/CVXPY_LP/HEURISTIC。
- **第57页，第4—13行**（全文L2671—L2680）；3.5.4，prcp_reverse_target字段表第6—9行。原文要点：配置目标值、GE/LE/EQ、目标权重与生效月份。
- **第51页，第15—20行**（全文L2332—L2337）；3.5.3，R2“加载指标项校验”。原文要点：weight总和＝100，target_value必须为正数。

**问题及影响：**现有章节已经有目标配置和算法选项，但尚未把本期“调整什么、如何评分、哪些条件必须满足、求不到怎么办”写成开发可照做的规则。仅生成24个月数据，不能等同于完成了目标驱动反算。

**本期最小优化建议：**本期只选一种已能实现的求解方式和一组可调变量，其他算法选项隐藏。补一页规格，写清：可调节点/规模及上下限、固定的价格和期限假设、目标函数或评分规则、硬约束、权重处理及无可行解返回方式。目标值是否允许0或负数，按本期指标逐项确认，不默认适用于所有指标。结果至少返回“是否可行、目标实际值、差距、调整方案”；使用启发式求解时称“可行/推荐方案”，不承诺全局最优。

**可后续完善：**强化学习、多算法自动选择、多周期复杂非线性优化和全局最优证明不作为本次上线门槛。

**最小验收点：**至少跑通一个有解场景及一个目标不可达/约束冲突场景；后者有清楚原因，不用空结果或模拟结果冒充成功。

### 问题06｜模型参数、训练产物与反算之间需要明确接入边界

**处理级别：启用模型时补齐；可先不启用在线训练。**

- **第41页，第4—8行**（全文L1925—L1929）；3.4.2，参数维护与模型训练流程。原文要点：每个参数关联指标；训练返回loss、mae/rmse/r2及模型产物。
- **第42页，第30—49行**（全文L1972—L1991）；3.4.3，第5—7条规则。原文要点：要求kpi_id、RATIO/AMOUNT/FLAG、default_value/current_value。
- **第47页，第1—10行**（全文L2166—L2175）；3.4.4，prcp_model_param字段表第5—10行（接第46页）。原文要点：实际表使用param_value、FLOAT/INT/CATEGORICAL；参数表未列默认值/当前值及关联指标字段。

**问题及影响：**业务参数规则与模型参数表不是同一套定义；训练说明中的模型产物，怎样绑定到具体一次反算也未充分约定。这不意味着本期必须建设完整训练平台，但启用相关功能前需要把读写关系确定下来。

**本期最小优化建议：**为快速跑通，可先用人工情景参数、固定规则版本，或一个已验证的模型产物。未接入真实训练引擎时关闭训练入口，不生成模拟训练曲线。若本期接模型，仅补齐该模型的输入字段、输出字段、产物标识、版本、失败处理及反算绑定关系。参数方面只保留一套实际读写字段；不实现的默认值/继承等要求在本期范围中明确暂缓。业务参数与算法超参数区分，避免给每个算法参数强行绑定业务指标。

**可后续完善：**通用训练平台、自动寻参、复杂版本继承、多模型全生命周期治理后续完善。

**最小验收点：**一次反算能够说明使用哪组参数/哪个模型产物，且更换指定参数或产物确实参与计算；规则模式不得因没有训练产物而被无意义地阻断。

### 问题07｜结果版本与情景隔离需要落实到执行批次

**处理级别：本期保留最小追溯；多情景可暂缓。**

**原文位置与依据：**

- **第33页，第51—56行**（全文L1635—L1640）；3.3.3，第6条“指标维护按版本归档”。原文要点：指标结果按数据日期＋版本归档。
- **第38页，第36—55行**（全文L1821—L1840）；3.3.4，prcp_kpi_value字段表第1—6行。原文要点：字段包括kpi_id、data_date、kpi_value、计算状态与日志。
- **第39页，第1—10行**（全文L1842—L1851）；3.3.4，同表第7—9行。原文要点：其余字段为删除标志与时间，完整表未列版本/执行批次字段。
- **第62页，第30—34行**（全文L2945—L2949）；3.6.3，R4“多情景一致性”。原文要点：同方案四情景只有rate_shock、deposit_loss_rate等情景参数不同。
- **第67页，第10—16行**（全文L3160—L3166）；3.6.4，“关键索引”“驾驶舱查询”。原文要点：结果通过scheme_code＋run_id＋节点＋日期＋偏移唯一；未展开情景与批次的绑定方式。

**问题及影响：**文档要求按版本归档、四情景对比，但指标结果表缺少版本字段，情景与执行批次的绑定也未写明。只靠方案编号查询，重跑后可能混读不同批次；没有情景字段本身不一定有错，也可以按run_id隔离，但必须约定。

**本期最小优化建议：**本期只跑BASE基准情景，其他情景入口先隐藏。每次执行生成独立run_id，结果查询和导出明确绑定该批次；指标结果至少关联到批次。保存一份本次输入数据、参数/规则及模型标识的轻量快照，必要时用JSON或文件实现，不重建复杂治理平台。若暂不实现独立业务版本号，把文档调整为“按执行批次留存”，避免界面承诺与存储不一致。

**可后续完善：**四情景联动对比、完整版本继承、跨版本归因和自动历史归档后续实现。

**最小验收点：**同一方案执行两次，旧批次结果仍可查；页面与导出来自同一批次；修改当前参数不会静默改写历史结果。

**本期最小验收用例：**
