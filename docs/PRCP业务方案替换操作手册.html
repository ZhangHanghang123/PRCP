适用范围与现状基线

0.1 本次场景定义：同一家银行 · 账户册重构 + 新基准日 + 口径联动

场景：同一家银行，但 ① 账户册要变（科目/层级/编码可能调整）、 ② 基准日要变（如 2025-12-31 → 2026-12-31）、 ③ 因账户册变了，指标计量口径也要变。

这个场景的特殊性：不是"换个日期"那么简单。账户册一变， 节点集、末级集、大类归属、决策变量、指标取数科目全部变， 而指标口径是"公式不变、实现变"—— 监管公式（LCR/NSFR/CET1 的定义）同一家银行通常不变， 但公式落到哪些科目上必须重做。这是本手册的核心难点。

0.1.1 三要素变化矩阵

变化要素变的是什么是否一定变连带影响
基准日数据时点一定变 基础数据、KPI 基期值、ESG 初始曲线、模型训练区间、目标值基准
账户册结构节点集 / 层级 / 编码 / 末级视调整幅度 决策变量、五大引擎系数、指标取数科目、驾驶舱汇总口径
指标计量口径指标「取哪些科目」随账户册变 六张参数表、评分回验、目标达成判定、导出结果

0.1.3 最重要的一条纪律：公式不变 ≠ 口径不变

同一家银行的 LCR 公式（HQLA / 净现金流出）不会变，但账户册重构后， 分子分母对应哪些节点一定会变。例如：
  • 「同业活期存款」被拆成「同业活期存款-一般户」+「同业活期存款-专用户」 → LCR 流出端的取数要改成两项合计
  • 「其他资产」被并入「其他资产（含应收）」→ NSFR 的 RSF 系数需要重新标定
  • 「国债」重分类为「交易性金融资产」→ EVE 的 is_asset 标记要跟着改
所以 §1.2 的产出必须是一张「指标 → 取数节点清单」表，而不是一句口径描述。

基础准备

一切的前置

1.1 账户册梳理与重构

账户册是全链路的骨架：五大引擎参数、基础数据、驾驶舱汇总、反算决策变量全部挂在节点上。 本次是同一家银行的账户册重构，所以不是从零建，而是在旧册基础上做差异映射。

步动作落点（表/页面）要点
1取得新年度科目体系—— 同一家银行的总账科目表 / 监管报表 / 内部管理口径表。重点问清：相比旧册哪些科目增删拆并
2逐条做新旧差异清单Excel 差异表（见下方格式） 这是本次场景的核心产出。每条差异标注变更类型与影响模块（用 §0.3 传导链）
3确定层级与末级新 prcp_coa_scheme + prcp_coa_node 旧册是 6 级 57 节点。新册若层级变了（如新增 IFRS9 层），末级必须承载余额（父级余额灌 0，展示层靠 roll-up）
4确定编码前缀约定node_code 当前代码按 S01=资产 / S02=负债 / S03=权益 / S04=表外 分类。 同一家银行通常沿用，但新增科目若插在编码中间会打乱顺序（如 S0101 与 S0102 之间插入新号）， 必须确认前缀语义不变，否则要改 §3.1 的两处分类规则
5标注决策变量节点备注 / prcp_sim_node_config 哪些末级科目参与算法优化（dynamic）、哪些固定（fixed）。旧册是 12 个决策变量 + 权益， 账户册变了这个集合通常要重圈
6录入系统前端「账户册维护」/prcp/coa 建新方案（如 ZX_COA_2026），设置 ACTIVE；不要在 ZX_COA 上原地改
7结构自检SQL 校验 父子闭环（无孤儿）、每条路径到根、末级占比、大类划分 100% 覆盖

1.1.1 新旧节点映射表（必须产出，是后续所有工作的桥梁）

这张表把旧账户册和新账户册连起来。有了它，指标口径才能迁移、参数才能复用、结果才能对比。

旧 node_code旧节点名 新 node_code新节点名 变更类型处理方式
S0101010100001.1.对公一般贷款S0101010100001.1.对公一般贷款 不变映射 1:1，参数与口径直接沿用
S0201010101001.1.1对公活期存款S020101010100 / S020101010101 对公活期存款-一般户 / -专用户 拆分 指标取数改为两项合计；参数按新科目分别配置；末级判定重标
S010104000000其他资产S010104000000其他资产（含应收） 合并取数点不变，但 RSF/权重系数要重新标定（合并了不同风险特征）
S030100000000交易性金融资产S030101000000（重分类至交易性） 重分类 大类归属变了 → 资产/权益口径、EVE is_asset 标记全部要重标
—（无）S010109000000新科目（IFRS9 三阶段） 新增补参数、决定是否进决策变量、补进指标取数
S020105000000已核销贷款—（取消） 取消从所有指标取数与参数中剔除，检查是否影响历史指标口径
变更类型只有 6 种：不变 / 拆分 / 合并 / 重分类 / 新增 / 取消。 每种对应固定的处理套路（见 §1.2.2），照着做就不会漏。

1.1.2 结构自检 SQL

-- 账户册结构自检（新方案入库后执行，四项应分别为 0 / 总数 / ≥90% / 1.0） SELECT (SELECT COUNT(*) FROM prcp_coa_node c LEFT JOIN prcp_coa_node p ON p.id=c.parent_id WHERE c.scheme_id=:new AND c.parent_id IS NOT NULL AND p.id IS NULL) AS 孤儿节点, COUNT(*) AS 总节点, SUM(c.is_leaf)/COUNT(*) AS 末级占比, SUM(c.node_code LIKE 'S0%' OR c.node_code LIKE 'ZX_%')/COUNT(*) AS 编码覆盖率 FROM prcp_coa_node c WHERE c.scheme_id=:new AND c.is_deleted=0; -- 新旧规模对比：节点数、末级数、层级分布差异是否在预期内 SELECT c.node_level, COUNT(*) 节点数, SUM(c.is_leaf) 末级数 FROM prcp_coa_node c WHERE c.scheme_id IN (:old, :new) AND c.is_deleted=0 GROUP BY c.node_level ORDER BY c.node_level;

1.2 指标逻辑与计量口径梳理（随账户册联动）

本次场景的关键：指标定义（监管公式）不变，但指标实现的取数科目随账户册变。 所以产出物不是一段口径描述，而是一张可执行的 「指标 → 取数节点清单」。

1.2.1 产出物：指标取数节点清单

kpi_code指标 口径角色旧取数节点 新取数节点变更类型
REG_LCR流动性覆盖率分子 HQLA S010103000000 国债 + S010101000000 贷款 S010103000000 + S010103001000(新增交易性)改
REG_LCR流动性覆盖率分母 净流出 S020101010100 对公活期存款 S020101010100 + S020101010101（拆分后合计）拆分
REG_NSFR净稳定资金比例ASF 系数表 S020101010200 对公定期存款 同左 + 新的长期稳定来源科目扩
REG_CET1核心一级资本充足率RWA 权重 S010101010000 对公一般贷款 同左，但 风险权重档位重标（新口径调整了部分行业权重）改
REG_ROE净资产收益率净利润 / 权益 S030100000000 权益 权益科目重分类后 取数点要跟着改重分类
REG_EVE经济价值变动is_asset/is_liability 逐节点资产/负债标记 重分类科目的标记全部重标重分类
这张表怎么用：一行 = 一个取数点。右列的每个节点都必须能在新账户册里找到； 找不到的，说明该指标在新体系下取不到数 → 要么改口径，要么标 missing（不参与评分）。

1.2.2 六种账户册变更 → 指标口径处理套路

变更类型对指标的影响处理套路
不变无映射 1:1，参数与口径直接沿用
拆分 1→N原取数点变多个 指标改为多项合计；N 项各自配参数； 合计口径与旧口径可比（否则目标值要重定）
合并 N→1多个取数点变一个 取数点收敛；但合并的科目风险特征不同，系数要重新标定（不能直接沿用旧系数）
重分类大类归属变 最危险的一类：影响资产/负债/权益总额、所有比率的分子分母、EVE 标记。 必须全量复核该科目在所有指标中的角色
新增可能补齐原缺口 补参数；判断是否纳入指标（纳入则目标值口径也要相应调整）
取消取数点消失 从指标取数中剔除；检查该指标在新口径下是否仍可算； 若成为关键缺口 → 该指标本期标 missing，不参与评分

1.2.3 其余指标要素（口径卡其余部分）

步动作落点要点
1盘点指标清单prcp_kpi_definition 当前 8 指标制：LCR / NSFR / CET1 / CAR / ROE / EVE / IBL / LR（REG_ 前缀）。新年度增删在此定义
2统一单位口径口径卡 全表统一用百分数（ROE 12.72 / LCR 148.92）。拆分合并时最容易出现"一个用小数一个用百分数"
3对齐目标值prcp_reverse_target 目标 + 约束方向（GE/LE）+ 权重 + 生效期。 账户册重构后若指标口径实质变化，目标值要重新与业务方确认（不是照抄旧目标）
4确认红线/段位prcp_kpi_score_rule/_segment 23 段制（红线→危险→预警→安全→过优）。同一家银行监管环境不变时可沿用； 若内部考核标准调整则重定
5标注缺口口径表"缺口"列 取不到数的指标明确标 missing（如 IBL/LR 当前是占位 0），不参与评分
6新旧口径可比性判断专项说明 逐指标回答：新口径下算出的值与旧口径是否可直接比较？ 若不可比（如 LCR 分子纳入了新的高流动性资产），就要在对比报告里标注断点， 否则双跑期会误判为"结果劣化"

1.3 指标计量参数梳理（五大引擎系数）

五大引擎（LCR/NSFR/CET1/EVE/NIM/ROE）的系数是按科目节点配置的 —— 账户册一变，参数表的行集合就变；口径一变，同一科目的系数也要重标。

参数表关键字段换册时的处理说明
prcp_lcr_paramscheme_code + node_code + 折算率（流入/流出） 按新册重灌拆分后每个新科目都要有折算率；合并的要重新标定
prcp_nsfr_paramASF / RSF 系数 按新册重灌 + 系数复核合并科目风险特征变化，RSF 不可直接沿用旧值
prcp_cet1_param风险权重 / 资本扣减项 按新册重灌 + 权重档位复核关注新年度监管权重调整
prcp_eve_paramis_asset / is_liability / duration 逐节点重标重分类科目必改；duration 随期限桶分布变化
prcp_nim_param / prcp_roe_param利率 / 收益率参数 按新册重灌FTP 定价随年度调整
顺序提醒：参数表的 scheme_code 指向账户册方案（ZX_COA）， 不是组合方案。新账户册建好后先灌参数、再做系数回验（用新基准日数据跑一遍引擎， 比对行方真实报表误差 ≤ 容差）。
参数复用策略（省时但不省心）： 用 §1.1.1 的新旧映射表做自动化迁移 —— 不变/改名的科目直接带过旧参数， 拆分的按比例或按新标定，合并的重标，新增的补，删除的丢弃。 但「不变」只指科目映射，参数值仍需抽样复核（至少覆盖每个指标的关键取数点）。
-- 系数覆盖率校验：应返回 0 行（每个有余额的末级科目在六张参数表都有系数） SELECT n.node_code, n.node_name FROM prcp_coa_node n JOIN prcp_data_basic b ON b.coa_node_id=n.id AND b.data_date=:d AND b.is_deleted=0 LEFT JOIN prcp_lcr_param p ON p.node_code=n.node_code AND p.scheme_code=:coa AND p.is_deleted=0 WHERE n.scheme_id=:coa AND n.is_leaf=1 AND n.is_deleted=0 AND b.current_balance<>0 AND p.id IS NULL; -- 参数表 scheme_code 指向账户册方案，新旧册各一套，切换后需确认指向 SELECT scheme_code, COUNT(*) 参数行数 FROM prcp_lcr_param WHERE is_deleted=0 GROUP BY scheme_code;

1.4 底层数据准备（新基准日 + 新账户册）

本次是新基准日 + 新账户册双变：数据要按新节点集、在新日期上重灌。 旧日期数据保留（可回溯、可对比）。

数据表粒度准备内容与要点
prcp_data_basic 核心新账户册 × 新基准日 每个末级科目一行：current_balance（余额，父级留 0）+ orig_m1..m60 / rem_m1..m60（64 期限桶：剩余现金流分布）。 注意 is_leaf 标记必须正确，驾驶舱末级判定依赖它； 节点集按新册，不是把旧册的行改个日期
prcp_rate_curv / prcp_rate_point曲线 × 期限点 国债/Shibor 曲线（EVE 折现用）。同一家银行沿用 CN_SOV_CNY，只需追加新日期点位； 若年度间收益率中枢变化大，新日期必须真实取数
prcp_kpi_valueKPI × 新日期 新基准日的真实指标值（用于 T0 基线与评分回验）。必须按新口径重算，不能沿用旧值
prcp_metric_coefficient账户册方案 × 节点 × 月份 5 指标逐月系数（反算结果的对比基线）。由引擎跑出或从历史导入；节点集变化后要重新生成
报表项映射prcp_rpt_* 表项与节点的映射随新册重配
新基准日的 ESG 初始曲线prcp_esg_scheme.initial_yields_json 见 §2.1，与数据准备同批完成
灌数纪律（两次事故换来的）：
  • 不要灌 prcp_data_balance —— 引擎已改读 prcp_data_basic，这张空表保留只为兼容
  • 灌数前 备份：CREATE TABLE prcp_data_basic_bak_YYYYMMDD AS SELECT * FROM prcp_data_basic;
  • 灌完跑总量对平：Σ(末级余额) 对比新行新基准日总资产/总负债报表，误差 ≤ 0.5% 才放行
  • 按新 data_date 新增，不覆盖旧日期（历史可回溯）
  • 节点集变了 → 不能只换日期：旧册的节点行在新册可能已不存在，需按新册重新组织

重新运行项目

数据就绪后

2.1 ESG 情景生成

利率情景是 EVE 与新业务模拟的输入。新基准日 + 新账户册后， 初始收益率曲线变了，情景必须重新生成，不能复用旧情景。

步动作落点要点
1取新基准日初始曲线prcp_rate_curv/point 新日期的国债收益率曲线；同一家银行沿用 CN_SOV_CNY 体系，只加点位
2配置 ESG 方案前端 ESG 场景工厂 / prcp_esg_scheme 关键参数：initial_yields_json（新曲线初始值）、n_factors（HJM 因子数，当前 5）、n_scenarios（当前 50）、n_steps、seed（可复现）
3生成情景prcp_esg_run → prcp_esg_scenario → prcp_esg_curve_point 跑完抽查：情景均值曲线应贴合初始曲线，无明显漂移
4曲线还原校验ESG 曲线还原页 挑 3 个情景做反推校验，期限点插值无断点
5与旧情景对比差异说明 新基准日利率中枢若明显变化，旧情景不可直接沿用； 记录新旧情景在关键期限点（如 1Y/5Y/10Y）的差异，供业务解读
已知缺口：接口文档里 ESG 经济情景生成属 P2-4 未完成项（25 端点）。当前库内 5 套方案/15 情景是既有数据 —— 换册前先确认生成链路可用性，不可用则走脚本离线生成后导入。

2.2 新业务模型重新生成（重训）

模型是基于账户册 + 训练区间数据拟合的，账户册和日期都变了 → 必须重训， 旧模型权重对不上新节点。

步动作落点要点
1发起训练任务模型管理 / prcp_model_train 指定：model_id（DNN_REG 等）+ coa_scheme_id（新账户册） + 训练区间 balance_date_from/to（覆盖新基准日）
2跟踪训练prcp_model_train_log 复用运行日志的轮次/进度/ETA 观测；失败看 error_message
3评估与定版prcp_model_train_result → prcp_model_version 比对 metrics（拟合优度/误差）；与旧版本 metrics 对比，劣化超阈值要查是数据问题还是模型问题
4模型参数迁移prcp_model_param n_candidates / acor_* / de_* / slsqp_* 等超参按新数据特性调整（建议先沿用默认跑基线）
-- 模型版本切换：新版本 ACTIVE、旧版本归档（不删） UPDATE prcp_model_version SET status='ARCHIVED' WHERE model_id=:mid AND status='ACTIVE'; UPDATE prcp_model_version SET status='ACTIVE' WHERE id=:new_version_id; -- 训练样本是否覆盖新基准日（应返回 0 行） SELECT t.id, t.train_code, t.balance_date_to FROM prcp_model_train t WHERE t.coa_scheme_id=:new_coa AND t.status='SUCCESS' AND t.balance_date_to < :new_base_date AND t.is_deleted=0;

2.3 组合反算验证（先跑通再改造）

步动作要点
1新建组合方案指向新账户册 + 新模型版本 + 新基准日；先各建一个 DNN / 蚁群 / 非线性方案
2配置目标约束按 §1.2 第 3 步的映射表录入；建议首个方案只用 4 个核心指标跑通
3跑首轮反算用现有引擎（QP 兜底）跑通全链路；日志里会打 WARN「标称算法无专属实现」属预期
4验证写回质量 ① 末级行数 = 末级节点数 × 月数（不能只有 17 行这种半截数据）
② is_leaf/category 标记非空
③ 资产余额 Σ(末级) 与报表对平（当前基线：资产 94,786 亿 / 负债 91,578 亿 / 权益 7,862 亿同量级）
5驾驶舱冒烟默认 run 能选中、KPI 非零、余额走势 24 月全非零、导出 xlsx 四个 Sheet 正常

改动点位置说明

3.1.2 强烈建议项（技术债清理，趁重构一起做）

  • 废弃 prcp_data_balance：从代码与文档中移除引用，或直接 DROP（留备份表）
  • 科目匹配去硬编码：kpi_functions/*.py 里按节点名匹配的逻辑改为 node_code 驱动
  • 分类规则抽公共模块：一处定义、前后端共享（当前三处各写一份，已出过口径漂移）
  • 标称算法 ↔ 实际求解器显式化：ALGO_IMPL 已加 WARN，进一步把方案表单的算法下拉与实现清单对齐，未实现的标注"演示"

3.2 蚁群算法落地（当前最大的功能缺口）

现状：ANT_COLONY 标称方案实际跑的是 QP 兜底（引擎未实现）。本次账户册重构是补齐它的最佳时机 —— 新节点集、新期望，一次到位。否则新册上跑的仍是 QP。

步动作要点
1实现 ACOR 求解器参考决策中心契约（接口文档 PDF）：蚁群粗筛（m=20, k=5, max_iter=15）+ DE 差分进化（np=30, max_iter=10）+ SLSQP 精修；参数全部从 prcp_model_param 读
2接入轮次编排复用现有 _run_rounds：ALGO_ROUNDS['ACOR'] = max_iter（每轮登记状态/得分/ETA，日志面板已就绪）
3收敛曲线输出按契约 trace[]{algo, iter, best} 落库，驾驶舱加收敛曲线图
4对照验证同一目标下 QP vs ACOR 跑分对比：ACOR 得分应 ≥ QP（否则调参）
5性能压测57 节点 × 15 轮在 1CPU 服务器上的耗时；超 5 分钟需降 max_iter 或抽样节点
同样欠账的还有：DNN_NEURAL_NETWORK（真神经网络）与 NONLINEAR_SOLVER（真非线性求解）。建议按 ACOR → DNN → NLS 顺序排期，或先在方案表单把未实现项标注「演示算法」，管理预期。
注意：账户册重构后若仍用兜底 QP，新旧两册的算法行为差异会混入结果对比 —— 双跑期务必记录「本次实际使用的求解器」。
