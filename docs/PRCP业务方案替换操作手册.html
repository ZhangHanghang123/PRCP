适用范围与现状基线

0.1 三种替换场景

场景含义工作量说明
A. 换数据日期同一家银行，基准日从 2025-12-31 换到新年度（如 2026-12-31）小 账户册结构不变，主要是重灌基础数据 + 重跑模型；本文 §1.4/§2 为主
B. 换银行主体从中信银行换成另一家银行的账户册与数据中 账户册重梳、编码体系可能变（S01× 前缀约定）、五大引擎系数全部重算；本文全流程适用
C. 换口径/方法同一家银行，但指标口径或计量方法调整（如 EVE 改现值法）大 涉及代码改造（§3）为主，数据层可复用
本文按场景 B（最全）编写，A / C 场景按章节标注裁剪即可。

基础准备

一切的前置

1.1 账户册梳理

账户册是全链路的骨架：五大引擎参数、基础数据、驾驶舱汇总、反算决策变量全部挂在节点上。先定结构，再灌数据。

步动作落点（表/页面）要点
1取得新银行科目体系—— 总账科目表 / 监管报表 G01/G32 / FTP 口径表，三选一作为权威源
2确定层级与末级新 prcp_coa_scheme + prcp_coa_node ZX_COA 是 6 级 57 节点。新行可能 4~5 级，末级必须承载余额（父级余额灌 0，展示层靠 roll-up）
3确定编码前缀约定node_code 当前代码按 S01=资产 / S02=负债 / S03=权益 / S04=表外 分类。新行若沿用此约定则免改代码；否则必须改 _classify 与 _classify_node（见 §3.3）
4标注决策变量节点备注 / prcp_sim_node_config 哪些末级科目参与算法优化（dynamic）、哪些固定（fixed）；ZX_COA 是 12 个决策变量 + 权益
5录入系统前端「账户册维护」/prcp/coa 建新方案（如 BANK2_COA_2026），设置 ACTIVE；不要在 ZX_COA 上原地改
6结构自检SQL 校验 父子闭环（无孤儿）、每条路径到根、末级占比、大类划分 100% 覆盖
-- 账户册结构自检（新方案入库后执行，四项应分别为 0 / 总数 / ≥90% / 1.0） SELECT (SELECT COUNT(*) FROM prcp_coa_node c LEFT JOIN prcp_coa_node p ON p.id=c.parent_id WHERE c.scheme_id=:new AND c.parent_id IS NOT NULL AND p.id IS NULL) AS 孤儿节点, COUNT(*) AS 总节点, SUM(c.is_leaf)/COUNT(*) AS 末级占比, SUM(c.node_code LIKE 'S0%' OR c.node_code LIKE 'ZX_%')/COUNT(*) AS 编码覆盖率 FROM prcp_coa_node c WHERE c.scheme_id=:new AND c.is_deleted=0;

1.2 指标逻辑梳理

明确"算什么、怎么算、目标是什么"。输出一张指标映射总表，它是后面参数配置与验收的唯一依据。

步动作落点要点
1盘点指标清单prcp_kpi_definition 当前 8 指标制：LCR / NSFR / CET1 / CAR / ROE / EVE / IBL / LR。新银行增删指标在此定义（kpi_code 建议 REG_ 前缀保持一致）
2逐指标写口径卡文档（附录模板） 分子/分母取哪些科目、时点值还是均值、单位（小数 or 百分数）——单位口径必须全表统一，当前体系是百分数（ROE 12.72、LCR 148.92）
3对齐目标值prcp_reverse_target 每指标目标 + 约束方向（GE/LE）+ 权重 + 生效期；注意与评分分段表的量纲一致
4确认红线/段位prcp_kpi_score_rule/_segment 23 段制是监管红线 → 危险 → 预警 → 安全 → 过优。新银行的监管环境不同，段位边界要重定
5明确不可推导项口径表"缺口"列 列出缺数据列的指标（如 IBL/LR 当前就是占位 0），要么补数据源、要么明确标记 missing

1.3 指标计量参数梳理（五大引擎系数）

五大引擎（LCR/NSFR/CET1/EVE/NIM/ROE）的系数是按科目配置的，换账户册 = 全部重配。

参数表关键字段换行时来源
prcp_lcr_paramscheme_code + node_code + 折算率（流入/流出）新行流动性报表逐科目折算系数
prcp_nsfr_paramASF/RSF 系数NSFR 报表口径
prcp_cet1_param风险权重 / 资本扣减项资本管理办法权重表
prcp_eve_paramis_asset / is_liability / duration利率风险计量口径（重定价期限）
prcp_nim_param / prcp_roe_param利率 / 收益率参数FTP 定价与新行财务计划
顺序提醒：参数表的 scheme_code 指向账户册方案（ZX_COA），不是组合方案。新账户册建好后先灌参数、再做系数回验（用基准日数据跑一遍引擎，比对行方真实报表误差 ≤ 容差）。
-- 系数覆盖率校验：应返回 0 行（每个有余额的末级科目在六张参数表都有系数） SELECT n.node_code, n.node_name FROM prcp_coa_node n JOIN prcp_data_basic b ON b.coa_node_id=n.id AND b.data_date=:d AND b.is_deleted=0 LEFT JOIN prcp_lcr_param p ON p.node_code=n.node_code AND p.scheme_code=:coa AND p.is_deleted=0 WHERE n.scheme_id=:coa AND n.is_leaf=1 AND n.is_deleted=0 AND b.current_balance<>0 AND p.id IS NULL;

1.4 底层数据准备

数据表粒度准备内容与要点
prcp_data_basic 核心账户册 × 基准日 每末级科目一行：current_balance（余额，父级留 0）+ orig_m1..m60 / rem_m1..m60（64 期限桶：剩余现金流分布）。注意 is_leaf 标记必须正确，驾驶舱末级判定依赖它
prcp_rate_curv / prcp_rate_point曲线 × 期限点 国债/ Shibor 曲线（EVE 折现用）。若沿用 CN_SOV_CNY 只需追加新日期点位；换币种则新建曲线方案
prcp_kpi_valueKPI × 日期新银行基准日真实指标值（用于 T0 基线与评分回验）
prcp_metric_coefficient账户册方案 × 节点 × 月份5 指标逐月系数（反算结果的对比基线）。由引擎跑出或从历史导入
报表项映射prcp_rpt_*若新行有专属报表（G01 等），表项与节点映射重配
灌数纪律（上次事故的教训）：
  • 不要灌 prcp_data_balance —— 引擎已改读 prcp_data_basic，这张空表保留只为兼容
  • 灌数前 备份：CREATE TABLE prcp_data_basic_bak_YYYYMMDD AS SELECT * FROM prcp_data_basic;
  • 灌完跑总量对平：Σ(末级余额) 对比新行总资产/总负债报表，误差 ≤ 0.5% 才放行
  • 新增数据一律 新 data_date，不覆盖旧日期（历史可回溯）

重新运行项目

数据就绪后

2.1 ESG 情景生成

利率情景是 EVE 与新业务模拟的输入。换方案后初始收益率曲线变了，情景必须重新生成，不能复用旧情景。

步动作落点要点
1配置 ESG 方案前端 ESG 场景工厂 / prcp_esg_scheme 关键参数：initial_yields_json（新曲线初始值）、n_factors（HJM 因子数，当前 5）、n_scenarios（当前 50）、n_steps、seed（可复现）
2生成情景prcp_esg_run → prcp_esg_scenario → prcp_esg_curve_point 跑完抽查：情景均值曲线应贴合初始曲线，无明显漂移
3曲线还原校验ESG 曲线还原页 挑 3 个情景做反推校验，期限点插值无断点
已知缺口：接口文档里 ESG 经济情景生成属 P2-4 未完成项（25 端点）。当前库内 5 套方案/15 情景是既有数据 —— 换行前先确认生成链路可用性，不可用则走脚本离线生成后导入。

2.2 新业务模型重新生成（重训）

步动作落点要点
1发起训练任务模型管理 / prcp_model_train 指定：model_id（DNN_REG 等）+ coa_scheme_id（新账户册） + 训练区间 balance_date_from/to
2跟踪训练prcp_model_train_log 复用运行日志的轮次/进度/ETA 观测；失败看 error_message
3评估与定版prcp_model_train_result → prcp_model_version 比对 metrics（拟合优度/误差）；通过后设新版本为 ACTIVE，旧版本保留不删
4模型参数迁移prcp_model_param n_candidates / acor_* / de_* / slsqp_* 等超参按新数据特性调整（建议先沿用默认跑基线）
-- 模型版本切换：新版本 ACTIVE、旧版本归档（不删） UPDATE prcp_model_version SET status='ARCHIVED' WHERE model_id=:mid AND status='ACTIVE'; UPDATE prcp_model_version SET status='ACTIVE' WHERE id=:new_version_id;

2.3 组合反算验证（先跑通再改造）

步动作要点
1新建组合方案指向新账户册 + 新模型版本 + 新基准日；先各建一个 DNN / 蚁群 / 非线性方案
2配置目标约束按 §1.2 第 3 步的映射表录入；建议首个方案只用 4 个核心指标跑通
3跑首轮反算用现有引擎（QP 兜底）跑通全链路；日志里会打 WARN「标称算法无专属实现」属预期
4验证写回质量 ① 末级行数 = 末级节点数 × 月数（不能只有 17 行这种半截数据）
② is_leaf/category 标记非空
③ 资产余额 Σ(末级) 与报表对平（当前基线：资产 94,786 亿 / 负债 91,578 亿 / 权益 7,862 亿同量级）
5驾驶舱冒烟默认 run 能选中、KPI 非零、余额走势 24 月全非零、导出 xlsx 四个 Sheet 正常

3.2 蚁群算法落地（当前最大的功能缺口）

现状：ANT_COLONY 标称方案实际跑的是 QP 兜底（引擎未实现）。换行是补齐它的最佳时机——新数据、新期望，一次到位。

步动作要点
1实现 ACOR 求解器参考决策中心契约（接口文档 PDF）：蚁群粗筛（m=20, k=5, max_iter=15）+ DE 差分进化（np=30, max_iter=10）+ SLSQP 精修；参数全部从 prcp_model_param 读
2接入轮次编排复用现有 _run_rounds：ALGO_ROUNDS['ACOR'] = max_iter（每轮登记状态/得分/ETA，日志面板已就绪）
3收敛曲线输出按契约 trace[]{algo, iter, best} 落库，驾驶舱加收敛曲线图
4对照验证同一目标下 QP vs ACOR 跑分对比：ACOR 得分应 ≥ QP（否则调参）
5性能压测57 节点 × 15 轮在 1CPU 服务器上的耗时；超 5 分钟需降 max_iter 或抽样节点
同样欠账的还有：DNN_NEURAL_NETWORK（真神经网络）与 NONLINEAR_SOLVER（真非线性求解）。建议按 ACOR → DNN → NLS 顺序排期，或先在方案表单把未实现项标注「演示算法」，管理预期。

8性能与容量 新行科目数若显著多于 57（如 120+），反算决策变量、ESG 情景点数、驾驶舱查询都会变慢。压测三个点：snapshot 响应 <2s、反算单轮 <5min、导出 <30s；服务器 1CPU 是瓶颈
9时间安排的日历风险 "年底"切换要避开：月末/季末结账日（数据不可用）、报表报送期（行方没人配合对数）、你的假期。建议 T-2 周冻结需求、T-1 周只修不加

6.2 回退方案（15 分钟内可执行）

-- 回退 = 切回旧默认 + 恢复被污染的数据（如有）。代码无需回滚（新旧并存设计） -- ① 默认方案切回（若默认是配置） UPDATE sys_config SET value='2026' WHERE key_='default_reverse_scheme'; -- ② 数据被污染时：软删坏 run（先查后删） SELECT id, run_code, start_at FROM prcp_reverse_run WHERE scheme_id=:new_sid AND status='SUCCESS' AND is_deleted=0; -- 人工确认后： UPDATE prcp_reverse_run SET is_deleted=1 WHERE id=:bad_rid; UPDATE prcp_data_reverse SET is_deleted=1 WHERE run_id=:bad_rid; -- ③ 极端情况：恢复备份表 RENAME TABLE prcp_data_basic TO prcp_data_basic_broken, prcp_data_basic_bak_20261231 TO prcp_data_basic;
为什么能快：整套替换是「新建并存」而非「原地覆盖」——旧方案/旧数据/旧模型版本全程保留，回退只是把默认指回去。
