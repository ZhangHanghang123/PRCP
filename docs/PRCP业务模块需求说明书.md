# **1. 概述**

## **1.1. 背景及必要性、现状和业务目标**

背景及必要性：随着利率市场化深化与资产负债管理精细化要求提升，商业银行需要将"账户册建模—报表表项管理—基础数据维护—指标体系构建—模型训练—组合反算"打通为一条端到端的经营计划编制链路。当前银行业务条线中，资产负债数据分散在 Excel、监管报表、经营计划模板等多处，缺乏统一的账户册（Chart of Accounts）作为数据底座，导致不同报表口径不一致、指标定义重复、模型参数难以版本化管理、压力测试与反算结果无法回溯。为支撑年度经营计划编制、多情景预测、监管指标达标分析等管理诉求，迫切需要构建一个面向经营计划与资产负债预测的平台，作为 ALMT（业务分摊/定价/现金流）和 ALMD/IALMD/CURV/IALM（监管报送与曲线管理）之间的"中间测算层"，将数据、指标、模型、反算统一治理。

现状：当前经营计划编制仍以线下 Excel 模板为主，账户层级依靠手工维护，报表口径由各部门自行定义，指标公式分散在 VBA 与工作表内；模型参数缺乏版本管理，组合反算依赖人工经验，难以对 24 个月现金流缺口和未来 20 年报表做出自动化预测；现有 PRCP v1.0 模块以"资金组算"为切入点，但定位过窄，未覆盖账户册、报表、指标、模型、反算等核心链路；产品功能菜单已梳理出 20 项二级菜单，涵盖账户册方案/结构、6 类报表、6 类指标 + 资产负债表、指标定义/维护、模型参数版本/参数/训练、组合反算方案以及用户/角色/字典管理等能力，亟需在新版平台中按业务链路完整落地。

业务目标：通过本次需求，搭建组合管理测算平台 PRCP 的 7 大业务模块（账户册维护、报表表项管理、数据维护、指标管理、模型管理、组合反算、系统管理），形成"账户册—报表—数据—指标—模型—反算"的端到端业务链路；统一账户册口径、统一报表模板、统一指标公式，实现指标按版本归档、模型按版本训练、反算产出可报告化；为经营计划编制提供自动化测算与多情景对比能力，提升测算效率与决策准确性；为 ALMD、IALMD、IALM 等下游监管报送模块提供指标输出接口，为 ALMT 上游业务计划数据提供导入通道，与现有五模块形成互补闭环。

## **1.2. 术语定义**

| **序号** | **术语名称** | **定义** |
| --- | --- | --- |
| 1 | 账户册（Chart of Accounts, COA） | 银行资产负债业务核算对象的层级化结构，按资产、负债、权益、收入、支出五大类型组织；是 PRCP 所有数据维护与指标计算的数据底座。 |
| 2 | 账户册方案（COA Scheme） | 一组账户册节点的集合，按业务用途打包（如"资负表方案""损益表方案"），方案内节点编码唯一。 |
| 3 | 报表定义（Report） | PRCP 管理的报表模板定义，共 6 类：资产负债表（BALANCE）、损益表（INCOME）、现金流量表（CASHFLOW）、关键指标报表（INDICATOR）、风险加权资产报表（RISK）、流动性报表（LIQUIDITY）。 |
| 4 | 报表表项（Report Item） | 报表内具体行/列项目，按树形层级组织，关联账户册节点，支持计算公式（DECIMAL/INT/TEXT）。 |
| 5 | 数据维护（Data Maintenance） | 按数据日期和报表结构维护各类指标数据（账务结果、关键参数、规模、价格、中收、资本与 RWA 假设），通过"取数逻辑定义"配置分子项、分母项的账户册节点。 |
| 6 | 资产负债表（Balance Sheet） | 数据维护子模块之一，按数据日期和账户册节点录入当前余额，并维护未来 24 个月每月现金流缺口（M1 缺口 - M24 缺口）。 |
| 7 | 指标定义（KPI Definition） | 系统需要用到的指标编码、名称、所属报表、计算公式、计量单位（%/BP/RATIO/AMOUNT）；公式可引用本报表内的报表表项。 |
| 8 | 指标维护（KPI Value） | 指标结果按"数据日期 + 版本"双维度归档，当前值、上期值、环比/同比、计算来源（MANUAL/MODEL/RECALC）。 |
| 9 | 模型参数版本（Model Parameter Version） | 同一类业务模型的不同参数配方（V1.0/V2.0 等），支持版本继承（父版本）、复制、状态管理（DRAFT/ACTIVE/DEPRECATED）。 |
| 10 | 模型参数（Model Parameter） | 模型参数版本下的具体参数项，关联指标定义，含参数编码、参数类型（RATIO/AMOUNT/FLAG）、默认值、当前值。 |
| 11 | 模型训练（Model Train Task） | 基于模型参数版本 + 资产负债表数据日期窗口，调用训练引擎执行训练，输出 loss 曲线、拟合优度（mae/rmse/r2）及模型产物 ID。 |
| 12 | 组合反算（Portfolio Reverse Calculation） | 给定加载指标项（指标 ID + 目标值 + 权重），选择模型版本触发反算，输出未来 20 年的资产负债表与关键指标预测结果。 |
| 13 | 取数逻辑（Data Extraction Logic） | 数据维护中定义指标计量的分子项和分母项，分子/分母项选择账户册结构的节点，支持多选；系统自动生成或允许手工调整计算公式。 |
| 14 | 公式引擎（Formula Engine） | PRCP 自研的纯 Python 表达式解析与计算模块，支持四则运算符、SUM/AVG/MAX/MIN/COUNT、ABS/ROUND/IF，并支持引用同报表内的报表表项编码。 |
| 15 | 物化路径（Materialized Path） | 树形账户册/报表表项存储字段 `path`，形如 `/1/2/3/`，用于加速子树查询与排序，配合 `parent_id` 自引用实现拖拽排序。 |
| 16 | 角色权限（RBAC） | 用户—角色—权限三级模型，权限 key 形如 `coa:read`、`model:train`，菜单（前端路由）与数据权限（按报表/版本）由角色统一控制。 |
| 17 | 审计日志（Audit Log） | 记录所有数据维护、模型训练、组合反算等写操作，操作人/操作时间/操作类型/操作对象/前后值 JSON 序列化，符合金融合规要求。 |
| 18 | 算法适配层（Algorithm Adapter） | 用户后续提供的算法基类与实现层，前后端不变，仅替换 `app/algorithms/` 下的算法文件即可接入新模型。 |
| 19 | 版本（Version） | 指标维护、模型参数、反算结果均按版本归档（V1.0/V2.0 等），可对比、可回溯，支持版本继承与复制。 |
| 20 | 多情景（Scenario） | 组合反算支持的多种预测情景，包括基准/乐观/悲观/压力情景，可横向对比 24 个月现金流缺口与关键指标达成情况。 |

## **2.1. 业务需求内容**

### **2.1.1. 整体业务流程**

本次需求涉及 PRCP 7 大业务模块、20 项二级菜单，覆盖账户册方案与结构定义、6 类报表定义与表项结构、6 类指标数据维护与资产负债表 24 月现金流缺口、指标定义与维护、模型参数版本与训练、组合反算方案以及系统管理。各特性条目之间存在明确的业务承接关系，构成"账户册建模 → 报表模板 → 数据维护 → 指标体系 → 模型训练 → 组合反算"的端到端业务链路。下图从平台使用方（账户册建模人员、报表配置人员、数据维护人员、分析师、模型训练调度员、反算方案发起人）的视角，按各角色在各阶段完成的事项描绘整体业务逻辑：

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐

│ 建模人员  │    │ 报表配置  │    │ 数据人员  │    │ 分析师   │    │ 调度员   │    │ 反算发起人│

   树形层级        表项结构       资产负债表       指标维护        训练任务        未来 20 年
                                                                       │
```

# **3. 特性条目详细说明**

## **3.1. 【F01】账户册维护功能**

### **3.1.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"账户册维护"，下设两项二级菜单：账户册方案定义、账户册结构定义。账户册（Chart of Accounts, COA）是 PRCP 平台所有数据维护与指标计算的数据底座，按资产、负债、权益、收入、支出五大类型组织为树形层级。账户册方案定义用于按业务用途打包一组账户册节点（如"资负表方案 BS_2026""损益表方案 PL_2026"），方案内节点编码唯一；账户册结构定义支持以"左侧树形结构 + 右侧节点详情"的左右栏布局进行节点的增、删、改、查、拖拽排序与批量导入。本特性条目支撑的业务场景包括：年度经营计划编制前建立账户册方案并梳理资产/负债/权益层级；报表定义时引用账户册方案作为数据底座；数据维护时通过账户册节点作为取数逻辑的分子/分母选项。

### **3.1.2. 业务流程**

账户册维护的业务流程分为方案定义和结构定义两步：

```
[账户册方案定义]                              [账户册结构定义]
  ┌───────────────────────┐                    ┌───────────────────────────────┐
  │ ① 新增方案            │                    │ ① 选择方案                     │
  │    - 填写方案编码      │   方案编码唯一     │ ② 左侧树形选择父节点           │
  │    - 填写方案名称      │   ───────────────▶ │ ③ 右侧填写节点详情             │
  │    - 填写描述          │                    │    - 节点编码/名称/层级         │
  │    - 状态：ACTIVE      │                    │    - 节点类型（5 选 1）        │
  │ ② 导入/导出方案列表   │                    │    - 排序                      │
  │ ③ 修改/软删除方案     │                    │ ④ 保存（编码唯一校验）         │
  └───────────────────────┘                    │ ⑤ 拖拽排序/批量导入            │
                                                └───────────────────────────────┘
```

流程说明：建模人员先在"账户册方案定义"中创建方案（如 BS_2026 资负表方案），保存后切换至"账户册结构定义"；在结构定义中先选择方案，页面左侧展示该方案下的树形结构（默认根节点"资产/负债/权益/收入/支出"），右侧展示当前选中节点的详情；新增子节点时填写节点编码（方案内唯一）、节点名称、父节点（树形选择）、节点层级（自动计算）、节点类型（ASSET/LIABILITY/EQUITY/INCOME/EXPENSE）、排序等字段并保存；支持拖拽排序、同级调整、批量导入（Excel 模板）与软删除（is_deleted=0/1）。

### **3.1.3. 业务规则**

| **序号** | **系统名称** | **业务规则名称** | **业务规则内容** |
| --- | --- | --- | --- |
| 1 | 组合管理测算平台PRCP | 方案编码唯一性 | 同一系统下账户册方案编码（scheme_code）全局唯一，不允许重复；删除方案时仅做软删除（is_deleted=1），编码仍受唯一约束保护。 |

| 9 | 组合管理测算平台PRCP | 状态字段语义 | 方案与节点状态统一为 ACTIVE（启用）/INACTIVE（停用）两态；INACTIVE 节点不参与数据维护与指标引用新建，但已存历史数据保留。 |
| 10 | 组合管理测算平台PRCP | 树形拖拽约束 | 拖拽排序仅允许同级之间调整顺序或将节点拖拽到另一父节点下；不允许跨方案拖拽；拖拽后由服务层重排同级 sort 字段并刷新 path。 |

## **3.2. 【F02】报表表项管理功能**

### **3.2.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"报表表项管理"，下设两项二级菜单：报表定义管理、报表结构定义。报表定义管理用于在系统中定义 6 类报表（资产负债表 BALANCE、损益表 INCOME、现金流量表 CASHFLOW、关键指标报表 INDICATOR、风险加权资产报表 RISK、流动性报表 LIQUIDITY），每类报表关联一个账户册方案作为数据底座；报表结构定义用于按树形层级定义具体报表表项（含表项编码、表项名称、父表项、数据类型 DECIMAL/INT/TEXT、计算公式、关联账户册节点 JSON、排序等），支持"左侧树形结构 + 右侧表项详情"的左右栏布局，并在树形结构上提供增三改功能（增/删/改/排序/复制/批量粘贴）。本特性条目支撑的业务场景包括：分析师在年度经营计划编制前定义各类报表模板并配置表项与账户册节点的映射关系；数据维护人员按报表与表项录入数据；指标定义时通过所属报表引用报表表项作为公式输入。

### **3.2.2. 业务流程**

报表表项管理的业务流程分为报表定义和报表结构定义两步：

```
[报表定义管理]                                [报表结构定义]
  ┌───────────────────────────┐                ┌──────────────────────────────────┐
  │ ① 新增报表                │                │ ① 选择报表                       │
  │    - 报表编码（唯一）      │ 报表编码唯一    │ ② 左侧树形选择父表项             │
  │    - 报表名称              │ ──────────────▶│ ③ 右侧填写表项详情              │
  │    - 报表类型（6 选 1）    │ 关联账户册方案  │    - 表项编码/名称/层级          │
  │    - 关联账户册方案        │                │    - 数据类型（DECIMAL/INT/TEXT） │
  │    - 描述/状态             │                │    - 计算公式                   │
  │ ② 导入/导出报表列表       │                │    - 关联账户册节点（JSON）      │
  │ ③ 修改/软删除报表         │                │    - 排序                       │
  └───────────────────────────┘                │ ④ 保存                          │
                                                │ ⑤ 增三改（增/删/改/排序/复制/批量粘贴）│
                                                └──────────────────────────────────┘
```

流程说明：报表配置人员在"报表定义管理"中创建报表（如 RPT_BS 资负表，类型 BALANCE，关联账户册方案 BS_2026），保存后切换至"报表结构定义"；在结构定义中先选择报表，页面左侧展示该报表下的树形表项结构，右侧展示当前选中表项的详情；新增表项时填写表项编码（报表内唯一）、表项名称、父表项、数据类型、计算公式、关联账户册节点（多选节点 ID 列表，JSON 存储）、排序等字段并保存；支持增三改功能（增、删、改、排序、复制、批量粘贴），修改报表结构时连带影响数据维护与指标定义的引用关系，需联动提示。

## **3.3. 【F03】数据维护功能**

### **3.3.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"数据维护"，下设七项二级菜单：账务结果指标、关键参数指标、规模指标、价格指标、中收指标、资本与 RWA 假设指标、资产负债表。前 6 类指标采用统一的"左侧树形账户册 + 右侧表项数据矩阵"布局，按数据日期和报表结构维护相关指标数据，支持取数逻辑定义（分子项、分母项选择账户册结构的节点，支持多选），支持导入导出；资产负债表为特殊子模块，按数据日期和账户册结构维护资产负债表数据，数据包含当前余额、未来 24 个月每月现金流缺口（M1 缺口 - M24 缺口），用于支撑模型训练与组合反算。本特性条目支撑的业务场景包括：数据维护人员按数据日期录入各类指标当前值并配置取数逻辑（分子项+分母项）；资产负债管理人员按账户册节点录入余额与 24 个月现金流缺口；模型训练模块读取资产负债表数据日期窗口；组合反算读取指标与资产负债表作为输入。

### **3.3.2. 业务流程**

数据维护的业务流程分为指标类数据维护和资产负债表数据维护两类，前 6 类指标共用同一流程，资产负债表为独立流程：

```

  │    - 表项编码/名称              │            │    - 当前余额（DECIMAL）         │
  │    - 分子项（账户册节点多选）   │            │    - M1 缺口 - M24 缺口          │

  └────────────────────────────────┘            
```

流程说明：6 类指标（账务结果/关键参数/规模/价格/中收/资本与 RWA 假设）共用同一布局：顶部筛选（分类筛选 + 数据日期 + 报表选择 + 新增按钮），左侧展示账户册树形结构，右侧展示表项数据矩阵。数据维护人员先选择报表，左侧选择账户册节点作为该指标的取数依据，右侧在表项行上配置分子项（账户册节点多选）、分母项（账户册节点多选），系统自动生成计算公式（如 `[分子项 SUM] / [分母项 SUM]`），允许手工调整公式；录入当前值后保存，支持预览计算结果。资产负债表为独立布局：按数据日期展示账户册节点列表，每行包含当前余额与 M1-M24 共 24 列月度现金流缺口，支持导入导出；缺口生成算法说明写入计算备注。

## **3.4. 【F04】指标管理功能**

### **3.4.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"指标管理"，下设两项二级菜单：指标定义、指标维护。指标定义用于在系统中定义需要用到的指标（含指标编码、指标名称、所属报表、计算公式、计量单位 %/BP/RATIO/AMOUNT、公式说明、状态），公式计算只能引用所属报表内的报表表项；指标维护用于对指标结果按数据日期和版本双维度进行维护（含当前值、上期值、环比/同比、计算来源 MANUAL/MODEL/RECALC）。本特性条目支撑的业务场景包括：分析师在系统中定义 KPI（净息差、资本充足率、流动性覆盖率、不良贷款率等）；指标结果由"模型训练"或"组合反算"任务自动生成并按版本归档，也可手工录入；模型参数维护时引用指标定义作为参数关联对象；组合反算时引用指标定义加载指标项。

### **3.4.2. 业务流程**

指标管理的业务流程分为指标定义和指标维护两步：

```
[指标定义]                                    [指标维护]
  ┌───────────────────────────────┐          ┌──────────────────────────────────┐
  │ ① 新增指标                    │          │ ① 选择数据日期 + 版本            │
  │    - 指标编码（唯一）          │          │ ② 展示指标结果表                │
  │    - 指标名称                  │          │    - 指标编码/名称               │
  │    - 所属报表                  │          │    - 当前值/上期值              │
  │    - 计算公式（引用报表表项）   │          │    - 环比/同比（自动计算）       │
  │    - 计量单位（%/BP/RATIO/AMOUNT）│       │    - 计算来源                    │
  │    - 公式说明                  │          │ ③ 手工调整当前值                │
  │ ② 导入/导出                   │          │ ④ [重算]（触发公式引擎）        │
  │ ③ 修改/软删除                 │          │ ⑤ [新增版本]                    │
  └───────────────────────────────┘          └──────────────────────────────────┘
```

流程说明：分析师在"指标定义"中创建指标（如 KPI_NIM 净息差，所属报表 RPT_KPI，公式 `(利息收入-利息支出)/生息资产平均余额`，计量单位 %），保存时由公式引擎预解析，校验公式合法性与变量引用；切换至"指标维护"页面，选择数据日期与版本，页面展示该版本下的所有指标结果（含自动计算的环比/同比与计算来源），允许手工调整当前值，点击"重算"按钮时由公式引擎基于当前所属报表的报表表项数据重新计算所有指标。

### **3.4.3. 业务规则**

| **序号** | **系统名称** | **业务规则名称** | **业务规则内容** |
| --- | --- | --- | --- |
| 1 | 组合管理测算平台PRCP | 指标编码唯一性 | 指标编码（kpi_code）在系统内全局唯一；删除指标时仅做软删除（is_deleted=1），编码仍受唯一约束保护。 |
| 2 | 组合管理测算平台PRCP | 所属报表必填 | 指标定义必须关联一个 ACTIVE 状态的报表；公式中引用的所有报表表项必须属于该所属报表。 |
| 3 | 组合管理测算平台PRCP | 计量单位四选一 | 计量单位（unit）限定为 %（百分比）/BP（基点）/RATIO（比率）/AMOUNT（金额）四类之一。 |

## **3.5. 【F05】模型管理功能**

### **3.5.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"模型管理"，下设三项二级菜单：模型参数版本维护、模型参数维护、模型训练。模型参数版本维护用于定义模型版本编码、版本名称、父版本（自引用，支持版本继承）、参数数量、状态（DRAFT/ACTIVE/DEPRECATED）；模型参数维护用于在版本下维护具体参数（含参数编码、参数名称、关联指标定义、参数类型 RATIO/AMOUNT/FLAG、默认值、当前值）；模型训练用于维护模型编码、模型名称，选择模型参数版本与资产负债表数据日期，点击开始训练调用训练方案进行训练并监控训练状态（含进度、loss 曲线、训练开始/结束时间、模型产物 ID）。本特性条目承接上游指标管理（KPI 定义）与数据维护（资产负债表）作为训练输入，向下为组合反算提供模型输出。

### **3.5.2. 业务流程**

模型管理的业务流程分为版本维护、参数维护、模型训练三个阶段：

```
[模型参数版本维护]   [模型参数维护]          [模型训练]
  ┌────────────────┐  ┌───────────────────┐  ┌──────────────────────────────────┐
  │ ① 新增版本      │  │ ① 选择版本         │  │ ① 新建训练任务                   │
  │    - 版本编码    │  │ ② 新增参数         │  │    - 任务编码/名称               │
  │    - 版本名称    │  │    - 参数编码       │  │    - 选择模型参数版本            │
  │    - 父版本      │─▶│    - 参数名称       │─▶│    - 选择资产负债表数据日期      │
  │    - 状态        │  │    - 关联指标       │  │ ② [开始训练] 调用训练引擎        │
  │ ② 复制版本      │  │    - 参数类型       │  │ ③ 监控训练进度（SSE）            │
  │ ③ 导入/导出     │  │    - 默认值/当前值  │  │ ④ 查看训练日志与 loss 曲线       │
  │ ④ 修改/软删除   │  │ ③ 批量导入         │  │ ⑤ 下载模型产物                   │
  └────────────────┘  └───────────────────┘  └──────────────────────────────────┘
```

流程说明：模型管理员在"模型参数版本维护"中创建模型版本（如 V1.0 基准版本），可指定父版本实现版本继承，支持复制版本（自动生成新版本编码）；切换至"模型参数维护"，在左侧选择版本，右侧维护该版本下的具体参数，每个参数关联一个指标定义（xlsx 明确要求）；切换至"模型训练"，新建训练任务（含任务编码、名称、模型版本、资产负债表数据日期），点击"开始训练"按钮触发训练引擎后台执行训练，前端通过 SSE 推送训练进度（loss 曲线、拟合优度 mae/rmse/r2、模型产物 ID），训练完成后支持下载模型产物。

## **3.6. 【F06】组合反算功能**

### **3.6.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"组合反算"，下设一项二级菜单：组合反算。组合反算用于在系统中新增反算方案，加载指标项（含指标 ID + 目标值 + 权重），选择模型版本，点击"反算"按钮触发反算执行；反算结果为报表未来 20 年的情况（含资产负债表、关键指标），支持多情景对比（基准/乐观/悲观/压力）、导出 Excel/PDF。本特性条目承接上游模型参数与指标定义作为反算输入，输出未来 20 年的资产负债与关键指标预测，为经营计划编制提供自动化测算与多情景对比能力。

### **3.6.2. 业务流程**

组合反算的业务流程分为方案新增、反算触发、结果查看三个阶段：

```
[新增反算方案]      [触发反算]                       [结果查看]
  ┌────────────────┐ ┌──────────────────────┐         ┌────────────────────────────────┐
  │ ① 方案编码      │ │ ① 点击 [反算] 按钮    │         │ ① 未来 20 年资负表              │
  │ ② 方案名称      │ │ ② 校验加载指标项     │         │    - 资产/负债/权益              │
  │ ③ 加载指标项    │ │ ③ 校验模型版本       │         │ ② 未来 20 年关键指标            │
  │    - KPI_CAR    │─▶│ ④ 异步执行反算       │─▶       │    - KPI_CAR/NIM/LCR           │
  │      目标 14%   │ │ ⑤ SSE 推送进度      │         │ ③ 多情景对比表                  │
  │    - KPI_NIM    │ │ ⑥ 完成后跳转结果页   │         │    - 基准/乐观/悲观/压力         │
  │      目标 1.85% │ └──────────────────────┘         │ ④ 24 月时间轴切换               │
  │ ④ 模型版本 V1.0 │                                  │ ⑤ [导出 Excel] [导出 PDF]       │
  │ ⑤ [保存]        │                                  │ ⑥ [保存为新版本]                │
  │   [立即反算]    │                                  └────────────────────────────────┘
  └────────────────┘                                  
```

流程说明：反算发起人在"组合反算"页面新建反算方案（含方案编码、名称、加载指标项 JSON 数组 [{indicator_id, target_value, weight}]、模型版本），点击"立即反算"按钮触发反算执行，系统校验加载指标项与模型版本，异步调用反算引擎执行；反算过程中通过 SSE 推送进度；完成后跳转至反算结果详情页，展示未来 20 年的资产负债表（资产/负债/权益逐年）与关键指标（KPI_CAR/NIM/LCR 等）的预测结果，支持多情景对比表（基准/乐观/悲观/压力 vs 反算目标对比）、24 月时间轴切换（拖拽滑块切换分析时点），支持导出 Excel/PDF。

## **3.7. 【F07】系统管理功能**

### **3.7.1. 特性条目及业务场景说明**

本特性条目对应一级菜单"系统管理"，下设三项二级菜单：用户管理、角色管理、字典管理。用户管理用于维护平台用户（含用户名、显示名、密码哈希、邮箱、角色、状态）；角色管理用于维护平台角色（含角色编码 admin/analyst/viewer、角色名称、权限列表 JSON 菜单 key 数组、状态），实现 RBAC 权限控制；字典管理用于维护平台字典（含字典分类与字典项，如 ASSET_TYPE 资产类型/CURRENCY 币种/TENOR 期限），为前端下拉选项提供数据源。本特性条目作为平台基础数据底座，配合 JWT + RBAC 实现用户认证与权限控制。

### **3.7.2. 业务流程**

系统管理的业务流程涉及三类实体的维护：

```
[用户管理]              [角色管理]              [字典管理]
  ┌────────────────┐    ┌────────────────┐    ┌────────────────┐
  │ ① 新增用户      │    │ ① 新增角色      │    │ ① 新增字典分类  │
  │    - 用户名     │    │    - 角色编码    │    │    - 字典类型  │
  │    - 显示名     │    │    - 角色名称    │    │ ② 新增字典项    │
  │    - 密码哈希   │    │    - 权限列表    │    │    - key/value │
  │    - 角色       │───▶│    - 状态       │    │    - 排序      │
  │    - 邮箱       │    │ ② 修改/软删除   │    │ ③ 修改/软删除  │
  │ ② 修改/软删除   │    └────────────────┘    └────────────────┘
  └────────────────┘
```

流程说明：系统管理员在"用户管理"中创建用户（含用户名、显示名、密码哈希、邮箱、角色关联、状态），支持编辑/软删除；在"角色管理"中维护角色（含角色编码 admin/analyst/viewer、角色名称、权限列表 JSON 数组绑定菜单 key）；在"字典管理"中维护字典分类与字典项（如 ASSET_TYPE 资产类型：现金/贷款/债券/...，CURRENCY 币种：CNY/USD/EUR/JPY， TENOR 期限：1M/3M/6M/1Y/3Y/5Y/10Y）。

### **3.7.3. 业务规则**

| **序号** | **系统名称** | **业务规则名称** | **业务规则内容** |
| --- | --- | --- | --- |
| 1 | 组合管理测算平台PRCP | 用户名唯一性 | 用户名（username）在系统内全局唯一；删除用户时仅做软删除（is_deleted=1），用户名仍受唯一约束保护。 |
| 2 | 组合管理测算平台PRCP | 密码哈希存储 | 用户密码以 bcrypt 哈希（bcrypt==3.2.2）存储，明文密码不落库；登录成功后签发 JWT Token。 |
| 3 | 组合管理测算平台PRCP | 角色绑定 | 每个用户必须绑定一个角色（role_id FK → sys_role.id）；删除角色时若已被用户引用，禁止硬删除。 |
| 4 | 组合管理测算平台PRCP | 角色编码唯一性 | 角色编码（role_code）在系统内全局唯一；系统内置 admin/analyst/viewer 三个基础角色不可删除与禁用。 |
| 5 | 组合管理测算平台PRCP | 权限列表 JSON | 角色权限列表（perm_keys）以 JSON 数组存储菜单 key（如 `["coa:read","coa:write","model:train"]`）；登录后由后端按角色返回权限清单控制菜单与按钮渲染。 |
| 6 | 组合管理测算平台PRCP | 字典分类与字典项 | 字典采用"字典分类 + 字典项"两级结构（prcp_dict_type / prcp_dict_item）；字典类型编码（dict_type）全局唯一。 |
| 7 | 组合管理测算平台PRCP | 字典项 key/value | 字典项（dict_item）以 key/value 列表存储；key/value 在同一字典分类下唯一；支持排序字段控制展示顺序。 |
| 8 | 组合管理测算平台PRCP | 软删除机制 | 用户/角色/字典的删除操作均仅做软删除（is_deleted=1）；已被引用的记录禁止硬删除。 |
| 9 | 组合管理测算平台PRCP | 状态字段语义 | 用户/角色状态统一为 ACTIVE（启用）/DISABLED（停用）两态；DISABLED 用户禁止登录；DISABLED 角色禁止被新用户绑定。 |
| 10 | 组合管理测算平台PRCP | JWT 鉴权 | 登录成功后签发 JWT Token（HS256 签名，含 user_id/role_id/iat/exp），后续请求 Header `Authorization: Bearer <token>` 鉴权；Token 默认有效期 8 小时。 |
| 11 | 组合管理测算平台PRCP | 数据权限 | 除功能权限外，支持数据权限按报表/版本控制读写范围，由角色权限列表中的数据权限 key 控制（如 `report:read:BS_2026`）。 |
