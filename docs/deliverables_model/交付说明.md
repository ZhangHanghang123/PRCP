## 二、四张图讲了什么

### 图 1：模型反算主链路（5 阶段 / 16 项）

```
模型建模 → 训练取数 → 算法求解 → 结果落库 → 预测值回流
```

| 阶段 | 要点 |
|---|---|
| 模型建模 | 模型 → 版本 → 参数 → 训练任务 四层配置 |
| 训练取数 | `prcp_data_balance` 余额序列、ESG 曲线、`param.formula` 派生特征 |
| 算法求解 | **三类算法三选一并行**：NONLINEAR_SOLVER / ANT_COLONY / DNN_NEURAL_NETWORK |
| 结果落库 | `predicted` + CI 双列；SUMMARY 汇总项衔接报表 |
| 预测值回流 | 指标计量 → 指标评分 → 趋势预警 |

> ★ 标注了**当前能力缺口**：预测值回写 `prcp_kpi_value` 未来期次**尚未实现**，
> 模型当前不消费指标值（详见图 1 STEP5）。

### 图 2：新业务现金流逐月滚动（6 阶段 / 20 项）

```
初始状态 → 年目标增量 → 当月投放 → 期限落桶 → 指标重算 → 排期汇总
```

完整计算过程：

| 阶段 | 关键公式 |
|---|---|
| 年目标增量 | type1/3 `B×参数%/100`；type2 `参数×单位换算`；type4 `年末余额−年初余额`（可为负=缩表） |
| 当月投放 | `add = 年目标×w[m]/100`；`release = rem_m[k]`；type1/2 `month_new=release+add`（回补）、type3/4 `month_new=add`（不回补） |
| 期限落桶 | `amount_v = month_new×pct/100` → `orig_mv += amount_v`（只进不出）、`rem_m{k+v} += amount_v`（**绝对到期月直落**） |
| 指标重算 | `new_current=B+add`；`new_avg=avg+add/2`；`new_wr=(avg×wr+Σamount×rate)/(avg+month_new)`；`new_interest=new_avg×new_wr/12` |
| 排期汇总 | 累加 60 月完整到期排期 → 每格都有值，形成时间轴 |

> ★ 标注了**利率单位陷阱**：`prcp_data_basic.weighted_rate` 存小数（0.045），
> `prcp_sim_term_ratio.interest_rate` 存百分数（3.5），直接相加会让月息虚高 100 倍。
> ★ 超 60 月归档长端桶 `y10/y15/y20/y30`。

### 图 3：指标计量计算链路（4 阶段 / 11 项）

```
取指标定义 → 准备上下文 → 逐项求值 → 结果落库
```

- 取定义：`prcp_kpi_scheme` → `prcp_kpi_definition` + `prcp_*_param`（折算系数）
- 准备上下文：完整业务表 current/adjusted/delta + **ctx 注入同方案其他指标该期值**
- 逐项求值：type=1 公式引擎 `evaluate(formula, ctx)`；type=2 函数执行器 `run_function_kpi(...)`
- 结果落库：`prcp_kpi_value`（指标编码 + 期次 + 当前值）

### 图 4：指标评分计算链路（4 阶段 / 12 项）

```
取评分规则 → 取待评价值 → 区间命中 → 出分落库
```

| 项 | 内容 |
|---|---|
| 规则 | `prcp_kpi_score_rule`（算法/满分/方向）+ `prcp_kpi_score_segment`（区间→分数） |
| **值来源无关** | 实测值 / 模型预测值 / 情景模拟值 —— 评分引擎无需知道值从哪来 |
| PIECEWISE | `score_min + (x−min)/(max−min) × (score−score_min)`；`score_min` 空则阶梯 |
| LINEAR | `y1 + (x−x1)/(x2−x1) × (y2−y1)`；超端点 clamp |
| 蒙特卡洛三档 | `conf_low` / `predicted` / `conf_high` 分别评分 → 悲观/中性/乐观 |
| 闭环 | 评分作为 DNN 训练奖励函数，驱动网络朝合规方向收敛 |

### 图 5：citideepalm 策略模型训练流程（7 阶段 / 26 项）

```
场景准备 → 系数采样 → 账户账本推演 → 指标计算 → 指标评分 → 损失计算 → 验证评估
```

| 阶段 | 关键内容 |
|---|---|
| 场景准备 | ESG 情景包（HJM 5 因子）、T0 账户工作簿、训练验证 95:5 切分、冻结 PCA 3 因子 |
| 系数采样 | τ（目标增长率）0.075~0.11、γ（评分损失权重）0.5~10、经营成本/增长/派息 |
| 账户账本推演 | `run_account_rollout` 逐月推进 360 月；策略网络输出 65 期限档配置；记录 post 状态 |
| **指标计算** | LCR（HQLA÷净流出，流入 75% 封顶）、NSFR（ASF÷RSF×调整系数）、EVE（六情景 ΔEVE 绝对值比率）、CAR |
| **指标评分** | 四指标 → 0~500 分（分段插值）→ 等权加权各 0.25 → 二次惩罚 `((500−q)/40)²` |
| 损失计算 | 目标损失（权益缺口平方）+ γ×月均惩罚 → 反传更新（梯度裁剪 0.2、早停耐心 5） |
| 验证评估 | 验证集**同样走指标计算+评分**，对比 growth/rule/total 三分量，导出模型包 + manifest |

### 图 6：citideepalm 策略模型推理流程（6 阶段 / 22 项）

```
加载模型 → 情景输入 → 账户账本推演 → 指标计算 → 指标评分 → 结果输出
```

| 阶段 | 与训练的关键差异 |
|---|---|
| 加载模型 | 读 `mm_policy_weights.pt` + `mm_yield_pca.pt`；校验 `policy_schema_hash`；**τ=0.0925、γ=5.25 固定，不再采样** |
| 情景输入 | ESG 情景包 + 策略输入 PCA 3 因子（180 月）+ T0 账户工作簿 |
| 账户账本推演 | `run_account_rollout` 推理模式（**不建梯度图**），同样 65 期限档决策 |
| **指标计算** | 与训练**完全同一套** `calculate_lcr_nsfr_indicators` / `delta_eve_from_cashflows` |
| **指标评分** | 与训练**完全同一套** `map_indicator_tensors` / `weighted_score_tensor` |
| 结果输出 | 期末权益与 ROE、月度台账明细、**★回传 PRCP**：预测业务量 → 指标计量 → 指标评分再算分 → 目标达成校验 |

> **训练与推理的共用点**（用户关注点）：
> 指标计算与指标评分在两条链路上是**同一套代码**（`prcp_rules/`），
> 差异只在**是否建梯度图、系数是否采样**。
> 推理侧算出的分数不会回传训练，但训练侧的评分作为**损失项**驱动网络朝合规方向收敛。

### ★ 关于「预览图」的说明（重要）

之前给你的 `_preview.png` / `.svg` 是**本工具自己用 SVG/PIL 渲染**的，
**不是 Visio 渲染的**。它只反映数据与坐标，**不反映 Visio 的实际渲染结果**。

连线的实际落点必须用几何模拟器或 Visio 实测验证 ——
`verify_connector_geometry.py` 按 Visio 的规则（局部坐标 + LocPin 基准）
模拟渲染每个形状，算出线实际画在哪。

### ★ 连线修复记录

#### 第 1 次修复（用户反馈「线跑到页面外、与卡片分离」）

根因：**Geometry 写成了页面绝对坐标**，而形状本身又有
PinX/PinY/Width/Height/LocPin → **双重定位冲突**，Visio 渲染时线飞了。

| | 修复前 | 修复后 |
|---|---|---|
| 端点跑出页面 | **38 个** | **0** ✅ |
| 连接点未命中卡片 | 4 个 | **0** ✅ |
| 拐点位置 | 2 个异常 | 0 ✅ |

同时修了 `card_widths` 存错（子栏宽 ≠ 实际卡片宽，差 0.25 英寸）。

#### 第 2 次修复（用户反馈「箭头没调正、变成水平短杠」）

根因：**Geometry 用了 4 点矩形围出细长框**。
Visio 按**路径末端切线方向**画箭头，而 4 点矩形的末端切线是**横切方向** ——
垂直线的末端切线变成 180°（水平向左），于是**向下的箭头被画成水平短杠**。

修复：Geometry 改为 **2 点路径**（`MoveTo` → `LineTo`），末端切线 = 连线方向。
配套：`LocPin = Pin − Begin`、加 `1D=1`、`EndArrowSize` 调到 4。

| | 修复前 | 修复后 |
|---|---|---|
| 箭头方向错误 | **15 条** | **0** ✅ |
| Geometry 与 Begin/End 自洽 | 23/23 | 23/23 ✅ |
