## 3. 模块详解

### 3.1 账户册维护

**业务定位**：定义银行的账户层级结构（COA = Chart of Accounts），是所有数据维护和指标计算的基础。

#### 3.1.1 账户册方案定义

**页面布局**：列表 + 新增/编辑抽屉

**字段**：
| 字段 | 类型 | 说明 |
|------|------|------|
| 方案编码 | VARCHAR(32) UNIQUE | 如 `ZXCOA_V1`、`COA_V6` |
| 方案名称 | VARCHAR(64) | 必填 |
| 状态 | ENUM('ACTIVE','INACTIVE') | 默认 ACTIVE |
| 描述 | TEXT | 选填 |

#### 3.1.2 账户册结构定义

**页面布局**：**左右栏**

**字段**：
| 字段 | 类型 | 说明 |
|------|------|------|
| 节点编码 | VARCHAR(32) | 必填，方案内唯一 |
| 节点名称 | VARCHAR(64) | 必填 |
| 父节点 | FK → 自身 | 树形关系 |
| 节点层级 | INT (1-5) | 自动计算 |
| 节点类型 | ENUM | ASSET/LIABILITY/EQUITY/OFF_BALANCE（**v2.5 国际化后**） |
| 排序 | INT | 同级排序 |
| 状态 | ENUM | ACTIVE/INACTIVE |

**当前实现**：
- 树形深度 5 层（L1=大类 / L2=中类 / L3=账户册项 / L4=子账户 / L5=明细）
- path 字段物化路径：`/L1_ASSET/L2_CASH/L3_CENTRAL_BANK`
- v2.5 国际化：L1_资产 → L1_ASSET，L1_负债 → L1_LIABILITY，L1_权益 → L1_EQUITY，L1_表外 → L1_OFF_BALANCE

---

### 3.2 报表表项管理

#### 3.2.1 报表定义管理

**6 类报表类型**：
1. **BALANCE** — 资产负债表
2. **INCOME** — 损益表
3. **CASHFLOW** — 现金流量表
4. **INDICATOR** — 关键指标报表
5. **RISK** — 风险加权资产报表
6. **LIQUIDITY** — 流动性报表

#### 3.2.2 报表结构定义

**左右栏 + 树形表项**，支持 SUM/AVG/MAX/MIN + 四则 + 取数逻辑（账户册节点）

### 3.3 数据维护（**v3 扩展到 9 类**）

| 类别 | 码值 | 说明 |
|------|------|------|
| 1.账务结果指标 | FINANCIAL | 资产负债表 + 利润表科目值 |
| 2.关键参数指标 | PARAM | 存款准备金率 / 流动性比例等监管参数 |
| 3.规模指标 | SCALE | 资产/负债/客户数等规模量 |
| 4.价格指标 | PRICE | FTP 利率 / 存贷利率 / 利差 |
| 5.中收指标 | FEE | 手续费及佣金收入 |
| 6.资本与RWA指标 | RWA | 资本充足率 / 风险加权资产 |
| 7.资产负债表 | BALANCE | 按账户册 × 数据日期 × 24 月的余额矩阵 |
| **8.基础数据表** | **BASIC** | **64+64 期限桶（v2.2 重构）** |
| **9.反算结果查询** | **REVERSE** | **反算引擎输出的未来 24 月预测** |

#### 3.3.8 基础数据表（**v2.2 重构**）

**64+64 期限桶结构**：
```
5 年内按月      60 桶：m1, m2, ..., m60（1-60 月）
长端固定桶       4 桶：y10, y15, y20, y30
─────────────────────────
合计           64 桶 × 2（orig + rem）= 128 列
```

**v2.1 → v2.2 变更**：
- ❌ 删除：`d1/d7`（1日/7日）
- ❌ 删除：`y1`（m12 已代表 12 月）
- ❌ 删除：未填充的 `m13-m60` 死列
- ✅ 新增：`m2/m4/m5/m7-m12`（1 年内按月拆分）
- ✅ 新增：`m13-m60`（2-5 年按月拆分）
- ✅ 保留：`y10/y15/y20/y30`（长端固定桶）

**页面布局**：参照 8. 基础数据表
- 顶部筛选：账户册方案 + 数据日期 + 日期偏移 + 单位 + 刷新/导出/导入/新增
- Tabs：账户册矩阵（二级表头）+ 大类汇总 + 账户册树
- 二级表头：`原始期限（#13c2c2）` + `剩余期限（#722ed1）` + `度量（#eb2f96）`

#### 3.3.9 反算结果查询（**v2.7 改造**）

**页面布局**（参考 8. 基础数据表样式）：
- 顶部筛选：反算方案 + 运行记录 + 预测月份 + 刷新/导出
- Tabs：账户册矩阵（二级表头）+ 大类汇总

**v2.7 变更**：
- 删除上方 4 个 KPI 卡（Run ID / 预测状态 / 数据行数 / 当前月份）
- 删除左侧账户册层级树
- 用 antd Table + 二级表头复刻 BasicDataSheet 样式
- 颜色统一：原 `#13c2c2` / 余 `#722ed1` / 度量 `#eb2f96`

## 6. v3.5 增量：新业务模拟方案

### 6.1 业务定位

> "如果按账户级 X% 月环比增长、按 SHORT 30% / MID 40% / LONG 30% 期限结构投放新业务，未来 24 月 / 60 月每个期限桶的金额、利息、风险如何变化？"

新业务模拟模块是 PRCP 在 v3.5 阶段**新引入的业务预测能力**。区别于组合反算（求最优化解），新业务模拟给定业务假设，按账户级推演 64+64 桶金额与主指标变化。

### 6.2 一级菜单

| 名称 | 路由 | 图标 | 配色 |
|---|---|---|---|
| 🎮 新业务模拟方案 | `/sim` | PlayCircleOutlined | 紫色 #722ed1 |

### 6.3 二级菜单

| 子菜单 | 说明 |
|---|---|
| 方案列表（`/sim/list`） | 方案 CRUD + 引擎计量入口 + 结果查看入口 |
| 方案配置（`/sim/config/:scheme_id`） | 节点配置 + 期限占比 + 新业务利率 |
| 模拟结果（`/sim/results`） | 按方案查看模拟结果汇总（按月/桶） |

### 6.4 字段定义

#### 6.4.1 方案信息
| 字段 | 必填 | 说明 |
|---|---|---|
| scheme_code | ✓ | 方案编码（全局唯一，逻辑删除后允许复用） |
| scheme_name | ✓ | 方案名称 |
| description | ✗ | 方案描述 |
| **data_date** | **✓** | **模拟起始月**（v3.5 必填，update 锁定不可改） |
| status | ✗ | ACTIVE / INACTIVE（默认 ACTIVE） |

#### 6.4.2 节点配置（每节点一行）
| 字段 | 必填 | 说明 |
|---|---|---|
| coa_node_id | ✓ | 关联 prcp_coa_node.id |
| current_balance | ✓ | 当前余额（元） |
| growth_rate | ✓ | 月环比增速（%，可负数） |
| effective_month | ✗ | 生效月（M0=全期，M3=第3月起，默认 M0） |

#### 6.4.3 期限占比（每节点 4 条：SHORT/MID/LONG/STRUCT）
| 字段 | 必填 | 说明 |
|---|---|---|
| term_type | ✓ | SHORT / MID / LONG / STRUCT |
| ratio | ✓ | 该期限占比（%，合计 = 100） |
| **interest_rate** | ✓ | **新业务利率**（%，v3.5 增量） |

### 6.5 校验规则

- 占比合计必须 = 100%（前端校验 + 后端二次校验）
- 同一方案下同一节点不能重复（uk_node）
- 期限占比修改后校验合计：失败回滚保存

### 6.6 引擎计量入口

「🚀 引擎计量」按钮触发：
1. 调用 `POST /engines/run` 提交方案
2. 后台 5 步算法（见技术架构 §10.2）
3. 写入 `prcp_sim_run`（status=RUNNING → SUCCESS/FAILED）
4. 写入 `prcp_sim_result`（每个节点 × 每个 date_offset + 64+64 桶 + 主指标）
5. 「📊 查看结果」入口启用

### 6.7 结果展示

- 整树布局：左侧账户册 DirectoryTree + 右侧节点结果
- 已跑过的节点显示紫色「⚡ 已模拟」Tag
- 点击未跑过的节点弹 info 提示
- 数据日期维度：M0（基期）~ M60（第 60 月）

### 6.8 状态机

```
DRAFT ──save──> READY ──engine.run──> RUNNING ──> SUCCESS / FAILED
                                  └─> REJECTED (占比≠100%)
```

### 7.4 KPI 多 Tab 直链实现

```jsx
// 菜单：`/kpi?tab=defs` `/kpi?tab=scores` `/kpi?tab=values` `/kpi?tab=schemes`
const [searchParams, setSearchParams] = useSearchParams()
const urlTab = searchParams.get('tab') as TabKey | null
const [tab, setTab] = useState<TabKey>(
  urlTab && ['schemes','defs','scores','values'].includes(urlTab) ? urlTab : 'schemes'
)

const switchTab = (k: TabKey) => {
  setTab(k)
  setSearchParams({ tab: k }, { replace: true })  // replace：避免污染历史
}
```

URL `?tab=` 与组件 state 双向绑定：
- 从菜单直接跳 `/kpi?tab=defs` → 默认打开"指标定义"
- 在页面内点 Tab → URL 同步，刷新页面 / 复制链接能复用
