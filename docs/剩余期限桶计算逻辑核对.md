## 一、你的业务描述（原文梳理）

1. 首先根据新增金额和节奏，算出未来 5 年每个月的新增量
2. M1 根据 M1 的新增额和到期分布，**更新剩余期限桶的金额**
3. M2 新增的时候，基于 **M1 更新后的剩余期限桶** 的金额进行 M2 的新增业务期限摆布
4. 以此类推，一直算到最后一个月
5. 每次算 M 月时，**M 月对应的剩余期限时间桶的金额就已经定了**
6. 这样推算一遍后，就形成了一个**最终的剩余期限桶对应金额的表**

## 四、一个需要澄清的关键点 💡

### `month_add` ≠ `month_new`（落桶用的是后者）

| 字段 | M1 值 | 含义 |
|---|---|---|
| `month_add` | 122.7192 亿 | 当月**分摊的净新增**（年目标 × 节奏权重）|
| `month_release` | 874.8342 亿 | 当月**从 m1 桶取走的到期额** |
| `month_new` | **997.5533 亿** | **实际投放总额** = add + release（目标类回补）|

**落桶用的是 `month_new`**：

```python
month_new = release + add          # 目标类（gt∈{1,2}）
apply_term_split(state, month_new, term_ratios, cur_month=k)
```

即：**目标增长类方式下，当月投放 = 净新增 + 到期续做**。
到期部分被重新投放出去（而不是让余额减少），这样才能保证余额净增长达到目标增速。

若改为「只落 `month_add`」，则余额每年会因存量到期而净减少，无法达成 5% 增长目标。

### 排期形态解读

**峰谷交替是正常现象**，源于「存量档位」+「新增错峰投放」的叠加：

| 形态 | 出现位置 | 原因 |
|---|---|---|
| **高峰**（800~5,500） | M1~M12 / M24 / M36 / M48 / M60 | 基准日存量按 loan 模板铺在 m1~m12/m18/m24/m30/m36/m48/m60/y10；此外 M24/M36/M48/M60 同时是「M1 投放 24 月期」的落点 |
| **中峰**（1,200~3,500） | M18 / M42 / M54 | 存量的 m18/m30/m48 档 + 相邻档位叠加 |
| **常青谷**（200~700） | M13~M23 / M25~M35 / M37~M47 / M49~M59 | 各月新增投放的 12/24/36 月期错峰到期 —— 这正是「每月都有投放」的体现 |

**关键观察**：M13~M23 之间没有空格，M25~M35、M37~M47、M49~M59 同理 —— 60 个月里每一格都有值，正是「未来 5 年每个月都有投放、按期限往后推算」的量化结果。
