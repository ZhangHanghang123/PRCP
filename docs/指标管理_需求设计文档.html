整体业务描述

1.1 业务背景

银行的价值管理（Value Management）需要回答：「我们的经营指标表现如何？离监管达标线还有多远？目标完成得怎么样？」

传统做法的痛点：

  • 指标口径分散 —— 同一个指标在不同报表里算法可能不一致，缺乏统一管理
  • 计算逻辑固化在代码里 —— 改一个指标算法要发版，业务人员无法自助调整
  • 监管指标难以量化评价 —— LCR/CET1 等指标只有数值，没有「好/坏」的评判
  • 历史数据无法对比 —— 只有当前值，看不到环比、同比与趋势

1.2 模块定位

指标管理是 PRCP 组算平台的「指标中枢」：负责指标的定义、计算、评分与维护， 为上层反算决策、报表分析、经营驾驶舱提供统一的指标数据与评分。

1.3 核心能力

能力说明
双引擎指标 支持公式指标（在页面写算式，如 生息资产/总资产*100）与 函数指标（挂载 Python 脚本，复杂逻辑如 LCR/NSFR 的多级折算）
多方案隔离 每个指标方案独立维护一套指标定义，互不干扰（如「监管口径方案」「内部考核方案」）
指标间引用 公式可引用同方案的其他指标（ctx 上下文注入），支持指标层层依赖
公式校验 保存前可调用校验接口试算，检查语法与依赖是否正确
多版本管理 同一指标同一日期可存多个版本（V1.0/V2.0），保留历史口径便于回溯
四期对比 自动维护当前值、上期值（环比）、去年同期值、评分，支持趋势分析
分段评分 支持阶梯评分（命中区间取固定分）与段内线性插值（区间内平滑过渡）
批量试算 一键计算某方案某日期的全部指标值与分数，也可单指标试算

1.4 与其他模块的关系

prcp_coa_node 账户册节点 ──┐
├──→ prcp_kpi_definition 指标定义 ──→ 指标值 ──→ 分数
prcp_rpt_item 报表表项 ──┘ │
　　　　　　　　　　　　　　　　　　↓
　　　　　　　　　　　　　　prcp_kpi_score_rule 评分规则 ──→ prcp_kpi_score_segment 分段

【下游】报表管理（嵌入指标值）｜ 反算决策（指标约束）｜ 经营驾驶舱（KPI 展示）
模块边界：本模块负责监管/经营指标的度量与评分， 不负责「指标目标值的制定」（属反算决策模块）与「指标达成率评价」（属报表分析）。

2.2 业务流程图

① 创建指标方案　　名称 / 编码 / 描述（如「REG 监管指标方案」）
↓
② 定义指标（indicator_type 二选一）
├─ type=1 公式指标 → 写算式，如 ROE*100，可引用同方案其他指标编码
└─ type=2 函数指标 → 指定 script_path + script_name，如 kpi_funcs.lcr::calc
↓
③ 绑定报表（rpt_id）　指标挂在报表表项下，便于报表取数
↓
④ 配置评分规则（可选）
├─ PIECEWISE 分段：[最小值, 最大值) → 分数，可开启段内插值
└─ LINEAR 线性：(指标值, 分数) 锚点对，锚点间线性插值 + 端点clamp
↓
⑤ 取值与评分
├─ 选数据日期 → 单指标【重算】或【一键试算全部】
├─ 公式引擎 evaluate(formula, ctx) 或 脚本执行器 run_function_kpi(...)
├─ 评分引擎：区间命中 → 段内插值 → 得分
└─ 写入 prcp_kpi_value（当前值/上期/去年同期/分数）
↓
⑥ 结果查看：指标维护 Tab（值+分数列表）｜ 方案总分汇总（总分/均分/已评分数）

阶段输入处理输出

2.4 关键业务规则

规则内容
方案隔离指标定义、评分规则、指标值均按 scheme_id 隔离，跨方案不可见
类型互斥indicator_type=1 用 formula；=2 用 script_path，二者不同时生效
依赖顺序公式引用其他指标时，被引用指标必须先算出值（未算出按 0 处理）
版本唯一(kpi_id, data_date, version) 定位一条指标值，重复试算为覆盖
评分可选未配评分规则的指标 score = NULL，列表显示 —
段内插值score_min 非空且区间宽度 > 0 时启用插值，否则阶梯评分
正则反向higher_is_better=0 时分数随指标值上升而下降（EVE 类指标）

3.2 状态与枚举

指标类型（PRCP_INDICATOR_TYPE）

值名称说明
1公式指标用 formula 字段的算式计算，简单逻辑优先用此类型
2函数指标挂载 script_path + script_name，复杂逻辑（LCR 分档折算等）用此类型

计量单位（PRCP_CALC_UNIT）

值名称展示格式
PERCENT百分比 %数值 + % 后缀
AMOUNT金额千分位 + 2 位小数
BP基点 BP数值 + BP
RATIO比率原值展示（通常已 ×100）

评分算法

算法段语义计算方式
PIECEWISE
分段		 [最小值, 最大值)
区间		 命中区间后：
· score_min 为空 → 阶梯评分，直接取该段 score
· score_min 有值 → 段内插值， score_min + (x-min)/(max-min) × (score-score_min)
LINEAR
线性		 (x, score)
锚点对		 锚点按 x 排序后线性插值；输入值超出锚点范围时按端点 clamp（取最近锚点分数）

5.1 表关系图

prcp_kpi_scheme 指标方案（1）
　　│ 1 : N
　　├─→ prcp_kpi_definition 指标定义（含公式/脚本）
　　│　　　│ 1 : N　　　　　　　1 : 1
　　│　　　├─→ prcp_kpi_score_rule 评分规则 ────→ prcp_kpi_score_segment 分段（N）

　　│　　　│ 1 : N

字段类型说明

5.2.4 prcp_kpi_score_segment —— 评分分段 ★核心表

字段类型约束说明
rule_idbigintNOT NULL所属规则
seg_orderintNOT NULL分段序号（升序判定）
min_valuedecimal(20,6)— 区间下界（含）；NULL = −∞
max_valuedecimal(20,6)— 区间上界（不含）；NULL = +∞
scoredecimal(8,2)NOT NULL 最大值分数：该段上界处的得分
score_mindecimal(8,2)NULL 最小值分数：该段下界处的得分。NULL = 不启用插值（阶梯评分）
segment_descvarchar(255)—分段说明（如「🟠 危险 0-150」）
score_min 的语义（2026-10-22 新增）
区间 [min_value, max_value) 映射到分数区间 [score_min, score]， 段内按 x 轴线性插值。score_min 为 NULL 时退化为阶梯评分（取 score）， 旧数据零迁移。

prev_year_valuedecimal(20,6)去年同期值（同比基期）

6.2 步骤拆解

步骤 1 · 构造上下文 ctx

取同方案下其他指标的该日期值，组成 {kpi_code: value} 字典。未算出按 0 处理。
ctx = { "ROE": 12.34, "LCR": 123.45, ... }
// 未算出值的指标按 0.0 填充，保证公式不会因缺键而失败

步骤 2-3 · 双引擎分派求值

类型求值方式适用
type=1
公式		 float(evaluate(formula, ctx))
formula 为空 → 返回 None		 简单算式，如 ROE*100、(A-B)/C*100
type=2
函数		 run_function_kpi(script_path, script_name,
   scheme_id, data_date, kpi_info, rpt_items, kpi_values)		 复杂逻辑，如 LCR 的多级折算、NSFR 的加权计算
公式指标　value = evaluate(formula, ctx)
函数指标　value = run_function_kpi(script_path, ..., rpt_items, ctx)

异常处理：FormulaError / FunctionKpiError / 其他异常 → 捕获并写入 calc_log，值返回 None

步骤 4 · 区间命中

// 按 seg_order 升序遍历，首个命中即返回
for s in segments（seg_order ASC）:
　　in_range = True
　　if s.min_value is not None and value < s.min_value:　in_range = False
　　if s.max_value is not None and value > s.max_value:　in_range = False
　　if in_range: matched = s; break

未命中 → matched=False, score=None，提示「所有区间均不匹配，请检查规则配置」
⚠️ 端点语义不对称：判定用 < min 与 > max， 所以 max_value 实际是闭区间上界（与 UI 标注的「最大值 <」略有出入）。 相邻段 [a,b) 与 [b,c) 在 b 处会同时命中前一段， 但因按 seg_order 升序遍历，实际归属前一段，符合预期。

步骤 5 · 段内插值评分

# 插值条件：两端分数都配了，且区间宽度 > 0
if score_min is not None and min_value is not None and max_value is not None and max_value > min_value:
　　ratio = (value − min_value) ÷ (max_value − min_value)
　　score = score_min + ratio × (score − score_min)　　mode = INTERPOLATED
else:
　　score = score　　　　　　　　　　　　　　　　　　　mode = STEPPED
场景配置行为
阶梯评分（旧行为）score_min = NULL命中即取 score
段内插值score_min 与 score 均有值，区间宽度 > 0 区间内按比例线性过渡
恒定段score_min = score插值公式自然退化为恒定
零宽峰点min_value = max_value 宽度为 0 → 强制 STEPPED（回填时已置 score_min = score）
端点外min_value=NULL 或 max_value=NULL 无法插值 → STEPPED

LINEAR 线性锚点模式

anchors = [(min_value or max_value, score), ...]　// 按 x 升序
if value ≤ anchors[0].x:　　score = anchors[0].score　　// clamp 下界
elif value ≥ anchors[−1].x:　score = anchors[−1].score　// clamp 上界
else: 找到相邻锚点 (x1,y1) (x2,y2)
　　　t = (value − x1) ÷ (x2 − x1)
　　　score = y1 + t × (y2 − y1)

步骤 6 · 落库

UPSERT prcp_kpi_value（kpi_id, data_date, version）
　　current_value　　= value
　　prev_value　　　= 上一期的 current_value　　// 环比基期
　　prev_year_value　= 去年同期的 current_value　　// 同比基期
　　score　　　　　　= 评分结果
　　calc_source　　　= MODEL（脚本计算）/ MANUAL（手工录入）
　　calc_log　　　　= 异常堆栈（成功时为 NULL）

6.3 核心公式汇总

环节公式
上下文ctx[kpi_code] = 该方案该日期其他指标的 current_value
公式求值value = evaluate(formula, ctx)
函数求值value = run_function_kpi(script_path, script_name, scheme_id, data_date, kpi_info, rpt_items, kpi_values)
区间命中min ≤ value ≤ max（min/max 为 NULL 时视为 ∓∞），按 seg_order 取首个命中
段内插值score = score_min + (value − min)/(max − min) × (score − score_min)
阶梯评分score = 该段 score（score_min 为 NULL 时）
线性插值score = y1 + (value − x1)/(x2 − x1) × (y2 − y1)，端点 clamp
方案总分total = Σ score　avg = total / scored_count

6.4 不变式（校验点）

不变式公式说明
上下文完备ctx 覆盖同方案全部其他指标缺键按 0，公式不报错
插值单调score ∈ [min(score_min,score), max(...)]插值结果不超出两端分数范围
端点一致score(x=min) = score_min
score(x=max) = score		插值曲线过两端点
边界连续段N.score = 段(N+1).score_min回填后相邻段得分连续
值分一致(kpi_id, data_date, version) 唯一重复试算为覆盖，不产生重复行
未评分标记score IS NULL未配规则时保持 NULL，前端显示「—」

8.6 常见问题排查

现象原因与解决
直接访问 ?tab=defs 显示「请先选择一个指标方案」 方案是数据范围的根，不是报错。需先在指标方案 Tab 点【进入】
