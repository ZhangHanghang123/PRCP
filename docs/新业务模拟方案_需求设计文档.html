整体业务描述

1.1 业务背景

银行的资产负债管理（ALM）需要回答一个核心问题：「未来 1~5 年，如果按设定的业务增长目标推进， 我的资产负债表、期限结构、利息收支会怎么演变？」

传统做法依赖 Excel 手工测算，存在三个痛点：

  • 无法覆盖全量科目 —— 账户册 57 个节点、20+ 层级，Excel 公式难以维护
  • 无法做期限滚动 —— 新增业务按期限占比落桶、逐月到期滚动的过程手工难以模拟
  • 无法做敏感性分析 —— 调整增速/节奏/期限结构后需要重算全部结果

1.2 模块定位

新业务模拟模块是一个「配置驱动 + 引擎计算」的资产负债预测工具： 用户在账户册的末级节点上配置「怎么增长、按什么节奏增长、增长出来的钱期限多长」， 引擎按月推演未来 60 个月的余额、期限结构、加权平均利率与利息收支。

1.3 核心能力

能力说明
多方案并行 可创建多个模拟方案（如「五年预算方案」「激进扩张方案」「基准情景」），各自独立配置与计算，支持方案间对比
全科目覆盖 账户册所有末级节点均可独立配置，引擎自动向上聚合到各级汇总节点
4 种增长方式 按业务性质匹配：目标增长百分比 / 目标增长绝对值 / 增长百分比 / 增长值
节奏控制 支持线性均衡、开门红、季末冲量、前低后高等投放形态，模拟真实的业务投放季节性
期限结构建模 新增业务按期限占比拆分到不同期限档，逐月滚动到期，反映资产负债的期限结构演变
全指标输出 每月输出当前余额、平均余额、加权平均利率、当月利息，以及 128 个期限桶明细
可追溯 每一行结果都记录当月年目标、节奏权重、分摊投放、到期释放、完整到期排期，可逐笔复盘

1.4 典型使用场景

  • 年度预算编制 —— 制定未来 5 年各业务条线的规模增长计划
  • 经营计划测算 —— 测算不同增长情景下的利息净收入、资产负债结构
  • 流动性压力测试 —— 输入不同增长假设，评估未来各月的到期缺口
  • 资源配置 —— 识别哪些科目在特定月份集中到期，提前安排资金调度
模块边界：本模块只负责新业务的增量测算， 不涉及存量业务的重定价、行为模型、利率情景模拟（这些由其他模块承担）。 本模块的输出是「如果业务按此配置增长，未来会怎样」。

2.2 业务流程图

【前置】账户册已导入基准日数据（prcp_data_basic，含余额与 64 个期限桶）

① 创建模拟方案　　选定账户册方案 + 基准日（默认最新数据日）
↓
② 选择参与测算的节点
├─ is_model_calc = 1 → 参与测算（配置增长方式/节奏/期限）
└─ is_model_calc = 2 → 存量保持（余额利率不变，仅记录到期）
↓
③ 逐节点配置四要素
├─ 增长方式 + 5 年增长参数　→ growth_config
├─ 投放节奏（12 月权重）　　→ rhythm
└─ 期限占比 + 各期限利率　 → term_ratio
↓
④ 运行引擎（POST /sim/schemes/{sid}/run?month_count=60）
├─ 逐月遍历 60 个月 × 全部节点
├─ 每笔投放落桶到「绝对到期月」并累加进 full_plan
├─ 60 月跑完后回填完整排期 → 批量落库
└─ 递归聚合 20 个 SUMMARY 汇总节点
↓
⑤ 结果查看
├─ 驾驶舱：全局汇总（分资产/负债/权益，单位亿元）
├─ 趋势区：余额/利率/利息的 60 月走势 + 投放节奏分解
└─ 节点级：账户册树 → 单节点 128 桶明细 + 排期追溯

2.4 关键业务规则

规则内容
增量守恒 12 个月的分摊投放合计 = 当年目标增量（Σ权重 = 100%）
占比守恒 期限占比合计必须 = 100%（应用层校验）
期限定位 第 M 月投放期限 v 的业务 → 落到第 M+v 月到期（绝对到期月口径）
目标类回补 growth_type ∈ {1, 2}（名称含「目标」）时，到期部分需重新投放，保证余额净增长达标
非目标类不回补 growth_type ∈ {3, 4} 时，到期自然出表，不回补
汇总节点不参与计算 is_aggregated = 1 的节点由引擎递归聚合产生，不可手工配置

6.2 桶语义（核心设计）

桶语义行为
orig_mv 原始期限为 v 个月的累计投放额 只进不出，不随月份变化 → 用于计算加权平均利率
rem_mk 距基准日第 k 个月到期的金额（绝对到期月） 第 M 月投放期限 v → 直落 rem_m{M+v}；到期时按 M 取走；每格只到期一次
为什么用「绝对到期月」而不是「剩余期限 + 每月前移」
  • 等价性：两条路径算出的余额轨迹完全一致（M1 29,575.44 亿 / M60 37,648.09 亿）
  • 可追溯：投放时一次定位到最终到期月，审计时能直接查「这笔钱什么时候还」
  • 零迁移成本：基准日时「剩余期限」=「距基准日到期月数」，存量数据无需转换

6.3 步骤拆解（以 M1 为例，S010101010000）

步骤 1 · 算当年净增目标

year_target = base_balance × year_value ÷ 100　　　// type 1/3
　　　　　 = 29,452.7204 × 5.0000 ÷ 100
　　　　　 = 1,472.6360 亿元
  • type 1/3：base_balance × 增速%
  • type 2：year_param × unit_scale（固定新增额）
  • type 4：year_param × unit_scale − 年初余额（年末余额锚定，年初锚定一次）

步骤 2 · 按节奏分摊到月

add = year_target × rhythm_weight ÷ 100
　　= 1,472.6360 × 8.3333 ÷ 100 = 122.7192 亿元

Σ(add over 12 months) = year_target × Σw/100 = year_target　// 增量守恒

步骤 3 · 按增长类型判断是否回补到期

planned_due = peek_due(state, M) = rem_m{M} = 874.8342　// 不清零，供结果留痕
release　　= take_due(state, M) = 874.8342　// 取走并清零

if growth_type in TARGET_GROWTH_TYPES: # {1, 2} 名称含「目标」
　　month_new = release + add　　# 到期回补，保证净增长达标
else:　# {3, 4}
　　month_new = add　　　　　　# 到期自然出表
关键区分：month_add ≠ month_new
字段M1 值（亿）含义
month_add122.7192当月分摊的净新增（年目标 × 节奏权重）
month_release874.8342当月从 m1 桶取走的到期额
month_new997.5533 实际投放总额 = add + release（目标类回补）
落桶用 month_new，到期部分被重新投放出去 → 余额才能净增长 5%

步骤 4 · 按期限占比拆分 + 落到绝对到期月

amount_v = month_new × business_ratio ÷ 100
落桶　　= rem_m{M + v}　　　　　　// 绝对到期月
记账　　= orig_m{v} += amount_v　　// 原始期限，只进不出
累加　　= full_plan[M + v] += amount_v　// 完整排期（见步骤 6）
期限占比投放额（亿） 落地格到期月新利率
12 月20%199.5107 rem_m13M133.20%
24 月30%299.2660 rem_m25M253.35%
36 月25%249.3884 rem_m37M373.50%
60 月25%249.3884 rem_y10M61+3.70%

M + v > 60 时按超出月数归档到 y10 / y15 / y20 / y30（10Y / 15Y / 20Y / 30Y）。

步骤 5 · 主表指标重算

new_cb = base_balance + add
　　　 = 29,452.7204 + 122.7192 = 29,575.4396 亿

new_ab = avg_balance + add ÷ 2
　　　 = 29,452.7204 + 61.3596 = 29,514.0800 亿

weighted_amount = Σ(amount_v × rate ÷ 100)　　　　　// 利率单位换算
　　　　　　　 = 199.5107×0.032 + 299.2660×0.0335 + 249.3884×0.035 + 249.3884×0.037
　　　　　　　 = 34.3657 亿

new_wr = (avg × wr + weighted_amount) ÷ (avg + month_new)
　　　 = (1,328.1336 + 34.3657) ÷ 30,511.6334 = 4.4654%

new_ia = new_ab × new_wr ÷ 12
　　　 = 29,514.0800 × 0.044654 ÷ 12 = 109.8277 亿
利率单位必须对齐：weighted_rate 是小数、interest_rate 是百分数， 加权求和前必须 ÷100，否则月利息虚高 100 倍。

步骤 6 · 完整 60 月排期回填（v2.4）

// 初始化：装入基准日存量
full_plan = {}
accumulate_plan(full_plan, state₀, 60)

// 每月投放时（apply_term_split 内）累加
full_plan[M + v] += amount_v

// 60 月跑完后回填每一行
apply_final_plan(row, full_plan)
　for tgt, amt in full_plan.items(): row[rem_{tgt}] = amt
配套改动：延后 INSERT
每月循环内用 all_rows.extend(rows_k) 暂存（不立即落库）， 60 月全部跑完 → 回填完整排期 → 分批（500 行/批）批量 INSERT。 这样才能让 M1 行也看到「未来 5 年每个月都有到期」的完整时间轴。
顺序要求：SUMMARY 聚合必须在批量 INSERT 之后执行（它用 INSERT...SELECT 聚合）。

6.4 核心公式汇总

环节公式
年目标year_target = f(balance, year_value, growth_type)
节奏分摊add = year_target × rhythm_weight ÷ 100
到期释放release = take_due(state, M)　// = rem_m{M}
投放总额month_new = (release + add) if gt∈{1,2} else add
期限落桶amount_v = month_new × business_ratio ÷ 100 → rem_m{M+v}
余额new_cb = base_cb + add　new_ab = avg_ab + add ÷ 2
加权利率new_wr = (avg×wr + Σ amount_v×rate÷100) ÷ (avg + month_new)
利息new_ia = new_ab × new_wr ÷ 12
汇总聚合SUMMARY[k] = Σ(所有后代叶子[k])（递归 CTE）

8.7 常见问题排查

现象原因与解决
结果金额是真实值的 100 倍 期限利率录成了小数（如 0.032），应为百分数（3.2）
到期释放远大于分摊投放 正常现象 —— 差额来自基准日存量到期，不是计算误差
余额同比远低于目标增速 检查 growth_type：若用 3/4（不回补），到期会净减少余额
部分月份到期额为 0 检查：① 底数期限桶是否回填；② 期限占比是否配了离散档位（如只配 m12/m24）
汇总节点数值为 0 汇总在批量 INSERT 之后执行；若为 0 检查叶子节点是否配置成功
「仅滚动」显示负数 前端公式错误（rolled − aggregated），应为 rolled_node_count 直接取值
汇总余额是节点数倍 汇总累加了汇总节点（is_aggregated 未过滤）
接口提示结果不完整 数据量超 limit（默认 20000），按月查询或调大 limit
