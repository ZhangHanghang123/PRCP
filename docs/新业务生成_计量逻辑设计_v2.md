# 新业务生成 · 计量逻辑设计（v2.0）

> 文档版本：v2.0
> 更新时间：2026-10-21
> 适用范围：PRCP 新业务模拟方案（`/prcp/sim/config/:scheme_id`）
> 引擎实现：`backend/app/services/calculate_engine/new_business/engine.py`
> 配置数据：4 张配置表（node_config / growth_config / term_ratio / rhythm）

---

## 〇、变更摘要（相对 v1.0）

v1.0 只有 2 类配置（`annual_growth_rate` + `term_ratio`），v2.0 引入 4 类配置，
并把「是否测算」提升为**一级分流开关**：

| 配置 | v1.0 | v2.0 | 作用 |
|---|---|---|---|
| 是否模型测算 | ❌ 无 | ✅ `is_model_calc` | **一级分流**：决定走测算分支还是存量保持分支 |
| 年化增长率 | ✅ 单值 | ⬆️ 拆表升级 | 单值 → 4 种增长方式 × 5 年分期 |
| 期限占比 | ✅ | ✅ 保持 | 到期落点 + 滚动 |
| 节奏配置 | ❌ 无 | ✅ **新增** | 12 个月权重，决定月度增长值分布 |

## 一、总体流程

```
                         ┌─────────────────────────────┐
                         │  遍历账户册末级（BUSINESS）   │
                         └──────────────┬──────────────┘
                                        │
                    ┌───────────────────▼───────────────────┐
                    │  读 is_model_calc（是否模型测算）       │
                    └───────┬───────────────────┬───────────┘
                            │                   │
              is_model_calc = 2（否）           is_model_calc = 1（是）
                            │                   │
        ┌───────────────────▼──────┐  ┌─────────▼──────────────────────────┐
        │ 【分支 A】存量保持        │  │ 【分支 B】模型测算                  │
        │  · 不读任何配置          │  │  · 读 3 类配置                     │
        │  · 余额/桶/指标 原地不动  │  │  · 增长 → 期限 → 节奏 → 滚动      │
        │  · 记 calc_note=         │  │                                    │
        │    "rolled-only"         │  │                                    │
        └──────────────────────────┘  └────────────────────────────────────┘
                                        │
                        ┌───────────────▼───────────────┐
                        │  聚合 SUMMARY 节点（递归 CTE） │
                        │  从所有后代末级按月聚合        │
                        └───────────────┬───────────────┘
                                        │
                        ┌───────────────▼───────────────┐
                        │  落 prcp_sim_result 快照       │
                        │  （M1 ~ M60，含 128 桶列）    │
                        └───────────────────────────────┘
```

**关键点**：分支 A 与分支 B **都写入** `prcp_sim_result`，用 `is_configured` 字段区分，
这样结果表结构统一，下游（驾驶舱/报表/指标）不需要写两套解析逻辑。

## 二、分支 A：不进行模型测算（`is_model_calc = 2`）

> 需求原文：「不进行模型测算的保持存量数据结构」

### 2.1 行为定义

| 项 | 处理方式 |
|---|---|
| 当月新增量 | `net_new = 0`，`month_new = rem_m1`（**仅自然到期滚动，不新增**） |
| 期限占比拆分 | **跳过**（不按 term_ratio 投放新业务） |
| 桶滚动 | **照常执行**（`roll_one_month`）——存量业务的自然到期必须滚动，否则期限结构会失真 |
| 主表指标 | `current_balance` 不变；`avg_balance` / `weighted_rate` / `interest_amount` 按存量口径重算 |
| 期限占比配置 | 即使配了也不生效（不拆分投放） |
| 增长配置 / 节奏配置 | **不读取** |

### 2.2 公式

```
# 当月投放量（仅到期，无新增）
month_new = rem_m1

# 余额保持
new_current = current_balance            # 不变
new_avg     = avg_balance
new_wr      = weighted_rate              # 不变（无新增业务，不稀释）
new_interest = new_avg × new_wr / 12
```

### 2.3 落库标记

```sql
is_configured = 0
calc_note     = 'M{k}={date}; growth=0.0%; rolled-only'
```

### 2.4 为什么「不测算」也要滚桶

存量数据不滚桶会导致：
- 期限结构失真：所有余额永远堆在短端桶，`rem_m1` 不归零
- 加权平均利率失真：新增与到期无法配对
- 与分支 B 的节点无法在 SUMMARY 层聚合（同一父节点下两种语义）

**结论**：不测算 ≠ 不滚动。分支 A = **只滚桶，不投放**。

## 三、分支 B：进行模型测算（`is_model_calc = 1`）

### 3.1 四步流水线

```
┌─────────────────────────────────────────────────────────────┐
│ 步骤 1  增长配置 → 确定「未来 5 年增长目标」                  │
│          prcp_sim_growth_config                             │
│          growth_type + year1_value ~ year5_value            │
└──────────────────────────┬──────────────────────────────────┘
                           │  年内目标 / 12 = 基准月增量
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤 2  节奏配置 → 确定「每月增长值分布」                     │
│          prcp_sim_rhythm（12 个月权重，和 = 100%）            │
│          rhythm_type = 1（线性）→ 每月等权 8.3333%            │
│          rhythm_type = 2（自定义）→ 按 12 月权重分配          │
└──────────────────────────┬──────────────────────────────────┘
                           │  month_add = 年内目标 × weight[m]/100
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤 3  期限占比 → 确定「到期落点」                           │
│          prcp_sim_term_ratio（term_value + business_ratio    │
│          + interest_rate，和 = 100%）                        │
└──────────────────────────┬──────────────────────────────────┘
                           │  按期限拆成多笔，分别落 orig_mv / rem_mv
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤 4  桶滚动 → 按月往前推                                  │
│          roll_one_month：m_v ← m_(v+1)，长端自循环            │
│          同时重算 avg_balance / weighted_rate / interest     │
└─────────────────────────────────────────────────────────────┘
```

> ⚠️ **顺序很重要**：先定「投放多少」（步骤 1+2），再定「投放到哪个期限」（步骤 3），
> 最后才滚动（步骤 4）。如果先滚动再投放，新投放的业务会被立刻推走一格。

---

### 3.2 步骤 1：增长配置 → 未来 5 年增长目标

**数据源**：`prcp_sim_growth_config`

| 字段 | 含义 |
|---|---|
| `growth_type` | 增长方式（字典 `PRCP_GROWTH_TYPE`） |
| `year1_value` ~ `year5_value` | 第 1~5 年增长参数（默认 0） |
| `unit` / `amount_unit` | 单位（`%` / `ABS`+`WAN`\|`YI`） |

#### 4 种增长方式的语义与换算

| growth_type | 名称 | `yearN_value` 语义 | 计算当年「目标增量」的公式 |
|---|---|---|---|
| **1** | 目标增长百分比 | 当年目标**增长率**（%） | `target_N = B_{N-1} × yearN_value / 100` |
| **2** | 目标增长绝对值 | 当年目标**新增余额绝对额**（万/亿） | `target_N = yearN_value × UNIT_SCALE` |
| **3** | 增长百分比 | 当年**期间增长率**（%，相对上年末） | `target_N = B_{N-1} × yearN_value / 100` |
| **4** | 增长值 | 当年末**余额绝对值**（万/亿） | `target_N = yearN_value × UNIT_SCALE − B_{N-1}` |

其中：
- `UNIT_SCALE`：万元 → `× 1e4`；亿元 → `× 1e8`
- `B_{N-1}`：第 N-1 年末的余额（`current_balance`）

#### growth_type 1 vs 3 的区别（易混淆，需重点确认）

| | 1 目标增长百分比 | 3 增长百分比 |
|---|---|---|
| 语义 | **规划目标**：银行年初定的目标增速 | **实际发生**：期间实际增速 |
| 用途 | 预算/规划场景（事前） | 复盘/校准场景（事后） |
| 引擎处理 | 目标增量 = 上年末余额 × 目标增速 | **相同算法**（都是相对上年末） |

> **待确认**：若 3（增长百分比）语义上应表示「相对期初而非上年末」，公式需调整。
> 当前实现按 v1.0 逻辑保留（相对上月末余额）。

#### 5 年目标展开到月

```
对于第 N 年（N = 1..5），取当年参数 yearN_value：
  year_target_N = 按 growth_type 换算出的目标增量（元）

当年 12 个月的「年内目标池」：
  year_pool_N = year_target_N

对第 N 年的第 m 月（M = 1..12）：
  年份索引     y = floor((M-1) / 12) + 1        // 第 1~12 月 → y=1，第 13~24 月 → y=2
  年内月份     m_in_year = (M-1) % 12 + 1
  年内剩余月数 remaining = 13 - m_in_year      // 12 月 → 12，1 月 → 12
```

### 3.3 步骤 2：节奏配置 → 每月增长值（新增能力）

**数据源**：`prcp_sim_rhythm`（12 个月权重，和 = 100%）

| rhythm_type | 名称 | 12 月权重来源 |
|---|---|---|
| **1** | 线性（默认） | 系统生成，每月 `100/12 = 8.3333%` |
| **2** | 自定义 | `prcp_sim_rhythm` 表配置的 12 行权重 |

#### 核心公式

```python
# 步骤 1 产出：当年目标增量 year_target_N（绝对金额，元）
# 步骤 2 产出：当年 12 个月的权重
weights = rhythm_weights  # [w1, w2, ..., w12]，和 = 100

# 第 M 月的新增投放量（不含到期）
month_add_M = year_target_N × weights[m_in_year - 1] / 100
```

#### 完整月度投放公式

```python
# 第 M 月
y          = (M - 1) // 12 + 1           # 第几年（1~5）
m_in_year  = (M - 1) % 12 + 1            # 年内第几月（1~12）

# ① 到期释放（存量桶自然到期）
release_M  = rem_m1

# ② 新增投放（本步骤算出的增长值）
add_M      = year_target[y] × rhythm_weight[m_in_year] / 100

# ③ 当月总投放量
month_new_M = release_M + add_M
```

> **示例**（线性节奏，第 1 年目标增量 1200 万）：
>
> | 月份 | 权重 | 新增投放 |
> |---|---|---|
> | M1  | 8.3333% | 100 万 |
> | M2  | 8.3333% | 100 万 |
> | … | … | … |
> | M12 | 8.3333% | 100 万 |
> | **合计** | 100% | **1200 万** |
>
> **示例**（自定义节奏「开门红」，第 1 年目标增量 1200 万，1 月权重 18%）：
>
> | 月份 | 权重 | 新增投放 |
> |---|---|---|
> | M1（开门红） | 18% | **216 万** |
> | M2 | 14% | 168 万 |
> | … | … | … |
> | M12 | 2% | 24 万 |
> | **合计** | 100% | **1200 万** |

**设计要点**：
- 节奏配置**只影响年内 12 个月的分布**，不影响全年总量（和恒为 100%）
- 线性 vs 自定义**总量完全相同**，只是时点分布不同 → 可做「节奏情景分析」
- 权重校验：和必须 = 100%（容差 ±0.01），由前端 + 后端双重校验

### 3.4 步骤 3：期限占比 → 到期落点

**数据源**：`prcp_sim_term_ratio`（`term_value` + `business_ratio` + `interest_rate`，占比和 = 100%）

```python
# 对 term_ratios 中每一行 (term_value=v, business_ratio=pct, interest_rate=r)：
amount_v = month_new_M × pct / 100          # 落到 v 个月期限的那一笔
bucket_key = f"m{v}"                        # v ∈ 1..60 → m1..m60

state[f"orig_{bucket_key}"] += amount_v      # 原始期限桶（用于加权平均利率）
state[f"rem_{bucket_key}"]  += amount_v      # 剩余期限桶（用于逐月滚动）
```

**示例**（当月投放 300 万，期限占比 12月 50% / 24月 50%，利率 3.5% / 3.8%）：

| 期限 | 占比 | 投放额 | 落地桶 | 利率 |
|---|---|---|---|---|
| 12 月 | 50% | 150 万 | `orig_m12` / `rem_m12` | 3.5% |
| 24 月 | 50% | 150 万 | `orig_m24` / `rem_m24` | 3.8% |

**校验规则**：
- `term_value` ∈ [1, 60]（超出用长端桶兜底）
- `business_ratio` 之和 = 100%（容差 ±0.01）
- `term_unit` 固定 `MONTH`

---

### 3.5 步骤 4：桶滚动

**沿用 v1.0 的 `roll_one_month`**，不做改动：

```
月桶：      新 m_v (1..59) = 旧 m_(v+1)；新 m60 = 旧 y10 / 60
长端桶自循环：
  新 y10 = 旧 y10 − 旧 y10/60  + 旧 y15/120
  新 y15 = 旧 y15 − 旧 y15/120 + 旧 y20/120
  新 y20 = 旧 y20 − 旧 y20/120 + 旧 y30/240
  新 y30 = 旧 y30 − 旧 y30/240
（orig_* 与 rem_* 各推一遍）
```

**主表指标重算**：

```python
new_current = current_balance + add_M                       # 本步：叠加新增投放
new_avg     = avg_balance + add_M / 2                       # 期初期末均值近似
new_wr      = (avg_balance × old_wr + Σ(amount_v × rate_v)) / (avg_balance + month_new_M)
new_interest = new_avg × new_wr / 12
```

## 四、完整公式汇总（分支 B）

```python
# ============ 输入 ============
base_balance   = current_balance                        # 上月末余额
growth_type    = growth_config.growth_type              # 1/2/3/4
year_values    = [year1_value, ..., year5_value]        # 5 年参数
rhythm_type    = node_config.rhythm_type                # 1=线性 2=自定义
rhythm_weights = [w1..w12]                              # 和 = 100%
term_ratios    = [(v1, p1, r1), ..., (vn, pn, rn)]      # p 之和 = 100%

# ============ 步骤 1：年目标 ============
for N in 1..5:
    if growth_type in (1, 3):                      # 百分比类
        year_target[N] = base_balance × year_values[N-1] / 100
    elif growth_type == 2:                         # 目标增长绝对值
        year_target[N] = year_values[N-1] × UNIT_SCALE
    elif growth_type == 4:                         # 增长值（期末余额）
        year_target[N] = year_values[N-1] × UNIT_SCALE − base_balance

# ============ 步骤 2：月度投放 ============
for M in 1..month_count:
    y         = (M - 1) // 12 + 1
    m_in_year = (M - 1) % 12 + 1

    release_M = rem_m1                                       # 到期释放
    add_M     = year_target[y] × rhythm_weights[m_in_year-1] / 100
    month_new = release_M + add_M

    # ===== 步骤 3：期限拆分 =====
    for (v, pct, rate) in term_ratios:
        amount_v = month_new × pct / 100
        orig_m{v} += amount_v
        rem_m{v}  += amount_v

    # ===== 步骤 4：滚动 =====
    roll_one_month(state)                                     # m_v ← m_{v+1}, 长端自循环

    # ===== 主表指标 =====
    new_current  = base_balance + add_M
    new_avg      = avg_balance + add_M / 2
    new_wr       = (avg_balance × old_wr + Σ(amount_v × rate_v)) / (avg_balance + month_new)
    new_interest = new_avg × new_wr / 12
```

## 五、与 v1.0 的差异对照

| 维度 | v1.0 | v2.0 |
|---|---|---|
| **是否测算分流** | 靠 `cfg_id is None`（有无配置）隐式判断 | ✅ 显式 `is_model_calc`（1=测算 / 2=否） |
| **增长参数来源** | `node_config.annual_growth_rate`（单值，全期不变） | `growth_config.year1~5_value`（5 年分期） |
| **增长方式** | 只有百分比 | ✅ 4 种（目标百分比 / 目标绝对值 / 百分比 / 增长值） |
| **月度投放量** | `current × rate / 100 / 12`（固定均分） | ✅ `year_target × rhythm_weight / 100`（节奏可配） |
| **节奏配置** | ❌ 无 | ✅ 12 个月权重（线性 / 自定义） |
| **存量保持节点** | 余额不变，但主表指标也走同一套公式 | ✅ 明确 `growth=0`、`month_new=rem_m1`、wr 不变 |
| **5 年以上（>60 月）** | `year_values` 缺失 → 沿用最后一年 | ✅ 建议：`M > 60` 时沿用 `year5_value`（需确认） |

## 七、边界与异常处理

| 场景 | 处理方式 |
|---|---|
| 未配置 `growth_config` | 视为 5 年参数全 0 → `year_target = 0` → 只滚桶不投放 |
| 未配置 `rhythm` | 默认线性（每月 `100/12 = 8.3333%`） |
| `rhythm_type = 2` 但 `prcp_sim_rhythm` 无数据 | 降级为线性，并在 `calc_note` 标注 |
| `term_ratio` 占比和 ≠ 100% | **阻断**（前端 + 后端双重校验，不允许保存） |
| `rhythm` 权重和 ≠ 100% | **阻断**（同上） |
| `growth_type = 4`（增长值）且目标值 < 当前余额 | `year_target` 为负 → 视为**净减少**（缩表场景），需业务确认是否允许 |
| `yearN_value = 0` | `year_target = 0`，当年不投放（自然到期滚动） |
| `M > 60`（预测期超 5 年） | 沿用 `year5_value`（**待确认**） |
| 节点无 `prcp_data_basic` 基础数据 | 跳过该节点（当前逻辑：`init_state is None` → continue） |
| `is_model_calc = 2` 但配了期限占比 | 期限占比**不生效**（不投放新业务） |
