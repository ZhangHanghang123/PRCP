桶v2.1 语义（前移）v2.4 语义行为与用途
orig_mv 原始期限 v 个月，每月前移 原始期限为 v 个月的累计投放额 只进不出，不随月份变化
→ 用于加权平均利率
rem_mk 剩余期限 k 个月，每月前移 距基准日第 k 个月到期的金额

关键顺序（v2.4）：每月循环内把投放落点累加进该节点的 full_plan， 结果行先暂存不落库；60 个月全部跑完后，才把完整排期回填到每一行的 rem_* 桶，再批量 INSERT。 这样才能让 M1 行也看到「未来 5 年每月都有到期」的完整时间轴。

计量过程逐步拆解（以 M1 · 2026-01 为例）

逐代入公式
步骤 1 · 算当年净增目标 growth_type = 1 目标增长百分比
按 growth_type = 1，目标增量以「上月末余额 × 目标增速」计算，单位 % 需 ÷100。
year_target = base_balance × year1_value ÷ 100
　　　　　 = 29,452.7204 × 5.0000 ÷ 100
　　　　　 = 1,472.6360 亿元
基数（上月末余额）29,452.7204 亿
第 1 年目标增速5.0000 %
→ 当年需增净目标1,472.6360 亿
说明：year_target 每月按当月余额重算，故同一年的 12 个月目标值会逐月上移 （M13 = 1,547.9786 → M24 = 1,620.4240 亿），这是「相对基数增速」的固有特征。
步骤 2 · 按节奏分摊到月 rhythm_type = 1 线性
线性节奏 12 个月均匀，每档 8.3333%。
add = year_target × rhythm_weight ÷ 100
　　 = 1,472.6360 × 8.3333 ÷ 100
　　 = 122.7192 亿元
当年净增目标1,472.6360 亿
M1 节奏权重8.3333 %
→ 当月分摊投放额（add）122.7192 亿
全年校验：12 × 122.7192 = 1,472.63✓ 与年目标一致
步骤 3 · 快照并取走当月到期 peek + take_due
判据：增长方式名称是否含「目标」。 TARGET_GROWTH_TYPES = {1, 2}（目标增长百分比 / 目标增长绝对值）→ 加上到期释放； {3, 4}（增长百分比 / 增长值）→ 不加，到期自然出表。
planned_due = peek_due(state, 1) = 874.8342 亿　（不清零，供结果表留痕）
release　　= take_due(state, 1) = 874.8342 亿　（取走并清零，用于扣减余额）

month_new = release + add　← 目标类，回补
　　　　 = 874.8342 + 122.7192
　　　　 = 997.5534 亿元
当月计划到期（peek，保留在结果表）874.8342 亿
当月实际释放（take_due，从桶中取走）874.8342 亿
→ 当月新增加值（投放总额）997.5534 亿
步骤 4 · 按期限占比拆分 + 落到绝对到期月 4 档期限
month_new = 997.5534 亿 × 各期限 business_ratio。
第 M 月投放期限 v 的业务 直接落到 rem_m{M+v}（不再靠每月前移推导）。
amount_v = month_new × business_ratio ÷ 100
落地格子 = rem_m{M + v}　（绝对到期月）
同时记　 orig_m{v} += amount_v（原始期限，只进不出）
　　　和　 full_plan[M + v] += amount_v（完整排期累加，见步骤 5）

步骤 5 · 累加完整 60 月排期 full_plan · v2.4
问题：如果只读 state，第 M 行只能看到「截至 M 月已投放」的落点 —— M1 时只有 M1 的投放进过桶，看不到 M2~M60 投放的未来落点。
解法：每个节点维护一个 full_plan 累加器，跨越全部 60 个月 把每一笔投放的落点都记进去，与是否已取走无关。
初始化：accumulate_plan(full_plan, state₀, 60)　← 装入基准日存量
每月投放：full_plan[M+v] += amount_v　（在 apply_term_split 内）

60 月跑完后：apply_final_plan(row, full_plan)
　　　　　　 for tgt, amt in full_plan.items(): row[rem_{tgt}] = amt
配套改动：延后 INSERT。原来每月循环结束立即落库， 现在改为 all_rows.extend(rows_k) 暂存， 60 个月全部跑完 → 回填完整排期 → 分批（500 行/批）批量 INSERT。 顺序要求：SUMMARY 聚合节点必须在批量 INSERT 之后执行， 因为它要用 INSERT ... SELECT 从已落库的结果行聚合。
步骤 6 · 主表指标重算 余额 / 利率 / 利息
更新 current_balance、avg_balance、weighted_rate、interest_amount。
new_cb = base_balance + add 　　　　　　　= 29,452.7204 + 122.7192 = 29,575.4396 亿
new_ab = avg_balance + add ÷ 2 　　　　　　　　　 = 29,452.7204 + 61.3596 = 29,514.0800 亿
weighted_amount = Σ(amount_v × rate) = 199.5107×0.032 + 299.2660×0.0335 + 249.3884×0.035 + 249.3884×0.037
　　　　　　　 = 6.3843 + 10.0254 + 8.7286 + 9.2274 = 34.3657 亿
new_wr = (avg × wr + weighted_amount) ÷ (avg + month_new)
　　　 = (29,514.0800×0.045 + 34.3657) ÷ (29,514.0800 + 997.5534)
　　　 = (1,328.1336 + 34.3657) ÷ 30,511.6334 = 4.4654 %
new_ia = new_ab × new_wr ÷ 12 = 29,514.0800 × 0.044654 ÷ 12 = 109.8277 亿
利率稀释：新投放利率（3.2~3.7%）低于存量 4.5%，故加权平均利率从 4.5000% 降至 4.4654%。 验算：隐含年化 = interest ÷ avg × 12 = 109.8277 ÷ 29,514.08 × 12 = 4.4654% ✓
